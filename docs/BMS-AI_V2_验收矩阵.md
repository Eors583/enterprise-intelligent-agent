# BMS-AI V2 需求追踪与验收矩阵

本文档把《企业协同智能系统_技术需求与实现方案_修订增强版》中的可验收需求映射到当前仓库。它是总门禁的入口，不以“存在页面”代替完成，也不以 Mock、静态 SQL 文本检查或空集合探针代替真实验收。

状态口径：

- `已实现`：领域模型、数据库约束、接口、用户入口和定向回归已形成闭环；
- `仓库门禁通过`：同一候选版已在全新数据库、全仓自动化和隔离恢复门禁通过；管理端浏览器基础巡检
  另有独立证据，但仍不包含 Electron 人工 UAT，也不代表生产验收；
- `人工 UAT`：仍需在目标 Electron/浏览器和真实业务数据中由业务负责人验收；
- `实施中`：本轮仍在合入或审查，不得对外宣称完成；
- `外部验收`：必须使用企业提供的真实供应商、身份提供商或生产基础设施，仓库内模拟器不能替代。

截至 2026-07-29，前一候选版已在全新隔离数据库完成 87 个 migration、完整回归、备份恢复
和只读治理演练。当前后续 P0 目录为 91 个 migration，本地代码自动化已通过，但
`127.0.0.1:55433` 无 PostgreSQL 监听且 Docker backend 调用超时，因此新增迁移尚未完成
隔离数据库、RLS/ACL 和恢复复验。管理端 dev `4274` 已登录并巡检 overview、knowledge、
agents、organization，preview `4273` 已打开且控制台无 CSP 错误；该证据属于前一候选版。
Electron UAT、非空语义 RAG、目标客户端人工 UAT 及生产外部系统仍未关闭。总体为 `No-Go`，
本表没有任何“生产可用”条目。

## 4. 总门禁执行顺序

1. 冻结本轮所有 migration，执行 Prisma `validate` 和 `generate`。
2. 在全新独立数据库顺序部署全部 migration，不访问既有受保护验收库。
3. 运行 PostgreSQL 集成、RLS/ACL 负向、跨租户、并发、幂等、恢复和哈希链门禁。
4. 运行 Contracts、API、Admin、Desktop、AI Runtime 的全部测试、类型检查、Lint、Prettier 和生产构建。
5. 启动 API、AI Runtime 和管理端，使用浏览器完成登录、组织、知识、角色、任务、Agent 对话、引用、工具审批、身份和治理页面 UAT。
6. 对真实模型、Embedding、Reranker、飞书、企业 IdP、SIEM/告警和异地备份分别保留联网验收证据。

当前代码自动化通过；前一候选版具有隔离恢复和管理端浏览器基础巡检证据。当前新增迁移的
隔离数据库/恢复复验、Electron UAT 与外部验收仍缺证据，因此总体状态保持 `No-Go`。只有
非空语义 RAG、目标客户端人工 UAT 和全部必需外部验收通过，才能把本矩阵改为生产可用。
