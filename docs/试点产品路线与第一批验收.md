# 企业智能体产品路线与分批验收

更新日期：2026-07-22

## 1. 产品目标与发布门禁

产品按三个可独立验收的版本交付，不以页面或 CRUD 数量作为完成标准。

| 版本            | 目标用户                | 核心门禁                                                 |
| --------------- | ----------------------- | -------------------------------------------------------- |
| V1 内部试点     | 1～2 个部门，20～100 人 | 稳定回答、权限内知识与可信引用、明确降级、基础恢复与监控 |
| V2 企业正式版   | 企业全员                | SSO/MFA/SCIM、发布治理、安全合规、高可用与灾备           |
| V3 智能执行平台 | 跨部门业务流程          | 工具权限、审批、补偿、人工接管、异步编排与结果审计       |

任何版本只有在自动化测试、故障演练和业务验收问题集同时通过后才能发布。

## 2. V1 工作包

### P0：回答链路

- Agent Run 必须具有排队、运行、成功、失败、取消和未知状态。
- 用户可以停止失败或运行中的任务，并在安全条件下重试；重试不得重复执行结果不确定的外部操作。
- Runtime 请求具有超时、幂等键、有限重试和敏感错误脱敏。
- API readiness 在启用 Agent Worker 时必须验证 AI Runtime，而不是只验证数据库。
- 前端必须展示运行状态、停止、重试、发送失败和网络恢复提示。

### P0：企业知识 RAG

- PDF、DOCX、Markdown、文本上传，受控对象存储，解析、切片和版本快照。
- 检索查询内执行租户、用户、部门及子部门权限过滤。
- 只有当前 READY 版本可被检索；引用绑定文档版本和切片，原文查看再次执行权限校验。
- 设置相关性阈值和无依据回答策略，模型输出的伪造引用不得进入消息账本。
- 管理员可在检索测试台复现权限范围、分数和命中切片。
- **试点阻断项：接入真实 Embedding/Reranker 并完成效果验收。未配置真实供应商时，关键词 + trigram 模糊排序只是词法检索，不得标记为企业级语义 RAG。**

### P0：账号恢复与防滥用

- 管理员强制重置密码和首次登录改密。
- 上线试点前必须具备忘记密码或一次性邀请链接、登录失败限速和会话吊销。
- 模型调用增加租户/用户并发上限、分钟级限流与月度配额。

### P0：运维底座

- 结构化日志和 request/run/tenant 关联标识。
- 数据库备份、恢复演练及可验证的 RPO/RTO。
- Agent Run、Outbox、解析失败、模型失败率和检索延迟告警。
- 测试、预发布、生产环境和数据库完全隔离。

### P1：员工体验和运营

- 未读、通知、搜索、分页、置顶/归档、复制、反馈和任务完成通知。
- 管理首页展示活跃人数、调用量、Token、费用、延迟、失败率、知识命中率、无答案率和好评率。

## 3. 第一批实现结果

本批完成了 API 就绪门禁：当 `AGENT_RUN_WORKER_ENABLED=true` 时，`GET /health/ready` 会在最多 3 秒内检查 AI Runtime 的 `/health/ready`，且只接受 HTTP 成功并返回 `status=ready`。连接失败、超时、非成功状态或无效响应均使 API 返回 503；响应不泄露 Runtime URL、上游正文或 Provider 诊断。Worker 关闭时明确返回 `aiRuntime=disabled`。

仓库中已经存在并纳入本批回归的试点基础：

- Agent Run 持久化、取消、重试、超时/不确定结果处理、可信引用校验；
- PDF/DOCX/TXT/Markdown 解析、切片、版本与入库任务；
- 部门树权限过滤、当前版本过滤、切片级引用及原文二次鉴权；
- 管理员检索测试台、无答案策略、回答点赞/点踩；
- 首次登录强制改密、管理员重置密码；
- Outbox 租约、退避、失败/未知状态和跨租户 RLS。

## 5. 第一批结束时的发布结论

第一批工程基线通过，但 **V1 仍为 No-Go**。进入 20～100 人真实试点前至少还要关闭四个阻断项：

1. Embedding + 向量检索 + Reranker，并用企业问题集验证召回和越权零容忍；
2. 忘记密码/邀请恢复闭环和登录失败限速；
3. 模型租户配额、并发控制、Token/费用/延迟指标；
4. 自动备份恢复演练及 Agent/Outbox/解析/检索告警。

这些门禁完成后进行 5～10 名种子用户的一周影子试用，再扩大到目标部门；任何越权引用、不可解释的重复执行或无法恢复的数据故障都应立即回滚试点。

## 6. 第二批实施状态（2026-07-21）

第二批没有改写或删除独立验收库 `enterprise_agent_acceptance`，也没有停止或重启当前开发服务。为避免把 `postgres:17-alpine` 的已有数据卷原地切换到 pgvector 镜像，语义能力使用独立数据库 `enterprise_agent_vector_acceptance` 验证。

### 已实现并纳入自动化验收

- 新增 pgvector 0.8.5、1536 维向量表、模型版本唯一键、HNSW cosine 索引、租户复合外键与 `FORCE RLS`；
- AI Runtime 新增相互独立的 OpenAI-compatible Embedding 和 Cohere-compatible Reranker 驱动，严格校验维度、数量、有限值、零向量和模型漂移；
- 入库采用“事务外生成 Embedding、事务内原子写切片和向量”，失败不会产生部分 READY 版本；重复正文切片不会被静默丢弃；
- 检索先在 SQL 中执行用户、任职、活动部门、知识库与当前 READY 版本权限过滤，再做词法/向量召回、RRF 融合和可选 Rerank；禁止候选不会发送给 Reranker；
- Exact vector search 为小规模试点正确性默认值；HNSW 需要通过按租户过滤的 Recall@K 对照评估后才允许启用；
- Agent Run 的远程检索移出长事务，派发前重新校验权限与当前版本；显式语义供应商故障会降级到词法并记录元数据，意外检索失败则保持 QUEUED；
- 管理端支持历史版本向量重建、检索模式/模型/分数/耗时/降级原因展示，并明确标记“仅词法检索”；即使 Query Embedding 成功，只要当前模型没有实际向量候选，也不得标记为 `HYBRID`；
- 租户级并发、分钟运行数、月度 Token 配额在同一 advisory lock 下校验、预留和结算；Runtime 未可信上报用量时保留保守 Token 占位，UNKNOWN 在 15 分钟不确定窗口内继续占并发、之后转人工对账且继续占 Token，具有外部 Run ID 的任务可由管理员触发对账；
- 生成输入在 API 派发前与 AI Runtime 调用前分别使用保守 UTF-8 上界执行 16k Token 预算预检，超限不会调用生成供应商；成功非空回答若可信上报 `0/0/0` Token 会在 Runtime、API 与数据库三层被拒绝；
- `agent_runs` 的租户 RLS 对普通与管理数据库角色统一生效；取消只有在供应商停止接口及状态查询确认后才落为 `CANCELLED`，无法确认时保留原状态与额度，避免供应商仍运行而平台提前释放额度；
- 管理端新增用量概览与 Owner-only 配额编辑，展示并发、速率、Token 已用与预留、未核实用量、平均执行延迟及供应商上报成本微单位；配额修改使用乐观锁并写审计；
- 登录失败限速持久化为认证专用的 HMAC 账户桶，并以原子预占消除并发闯入窗口；共享网络桶在成功登录时只回滚本次预占，不会清空同 IP 的其他失败历史；生产强制启用账户限速，网络桶仅在可信代理/IP 边界配置完成后显式启用；管理员重置密码会强制改密并吊销目标会话；
- 新增包含 ACL 的备份 manifest 与 SHA-256、受保护的隔离恢复演练、角色权限/外键/RLS/关键约束校验，以及 Outbox、Agent Run、未核实额度占位、租户配额、登录阻断、入库、指定 Embedding 模型向量缺口和备份/恢复新鲜度告警探针；dump 后采集的易变元数据仅作观察值，不再导致活跃写入误报恢复失败，保留策略只清理当前数据库的归档。

本次隔离验收已部署 26 个 migration；7 个真实数据库测试文件共 51 项通过，全仓 JavaScript/TypeScript 测试 350 项通过，AI Runtime 测试 130 项通过，类型检查、lint、Prettier 和生产构建均通过。第二批当时生成的 custom archive 已完成 SHA-256 校验、一次性恢复、权限、租户策略与用量约束验证，演练库随后删除。指定不可变 Embedding 模型的核心探针当时返回 `healthy`，但恢复报告同时显示 `knowledgeDocuments=0`，因此 `currentChunksMissingEmbeddings=0` 只是空集合通过，不能证明指定模型生成过真实向量，也不能替代供应商与企业问题集验收；第三批已把这一空集合误判改为 `not_ready` / `insufficient_evidence`。

### 第二批结束时仍未关闭的试点门禁

1. 必须配置真实 Embedding/Reranker 供应商，并以脱敏企业问题集验证 Recall@5、nDCG@10、MRR、无答案准确率、P95 延迟和 ACL 泄漏为零；代码路径通过不等于效果验收通过。
2. 第二批结束时，管理员重置密码只是恢复基线，忘记密码自助流程、一次性邀请链接、邮件投递和邀请状态仍未完成；公网部署还必须在可信代理/WAF 层增加 IP/设备限速与容量保护，数据库账户桶不能独自承担匿名随机标识流量。
3. 生成模型的成本统计只接受 Runtime 的可信上报；尚未提供不可变模型价格版本、币种、部门预算，以及覆盖生成、Embedding、Reranker 的统一用量账本。
4. 仓库已提供备份、恢复和探针脚本，但生产任务调度、加密异地存储、告警通道与值班响应尚未部署。
5. Manus 停止接口能够执行确认式取消；通用 OpenAI-compatible Chat Completions 没有标准取消资源，当前会诚实保留运行状态而不会伪报停止。选用的生产供应商若没有可确认取消协议，仍不满足“停止生成”发布门禁。

因此第二批结束时的结论仍是 **V1 No-Go**。第二批关闭了四个阻断项中的工程底座，但尚未完成真实供应商、业务问题集、账号自助恢复和生产运维接线。

## 7. 第三批实施与复验状态（2026-07-22）

第三批继续使用全新独立数据库 `enterprise_agent_third_batch_acceptance`。中间一次测试调用暴露出普通、认证、管理和 Outbox 角色连接 URL 可能混入根 `.env` 的隔离风险，并在 schema 前置检查阶段失败；最终测试运行器已强制把四个角色 URL 全部派生到 `TEST_DATABASE_URL`。两套预先标记为受保护的既有验收数据库从未建立连接；当前开发服务也没有因本批文档或复验工作被手动停止或重启。

### 已实现并纳入复验

- 在既有管理员强制重置基础上，新增枚举安全的忘记密码请求、一次性密码重置令牌、过期/撤销/单次消费控制，以及完成重置后的会话吊销；
- 新增成员邀请创建、列表、状态、重发、旧令牌撤销和接受邀请，接受后设置密码并激活成员与待入职任职；
- 恢复与邀请通知支持可选邮件供应商并记录投递状态，但邮件仍是 best-effort 非持久化投递：原始一次性令牌不会写入数据库，也没有进入可重放的 Outbox。进程在投递前退出时，`PENDING` 记录不能自动恢复，用户或管理员必须重新签发令牌；因此不能把“功能链路已实现”表述为“生产邮件闭环已完成”；
- 登录与恢复限速新增跨租户全局网络桶并在随机账户/令牌桶前检查，缺失地址进入固定 fail-closed 桶；每个 scope 通过事务 advisory lock 执行硬容量准入，容量满时拒绝落库，计数采用饱和增长。生产 Prisma 环境默认并强制启用网络限速，密码重置请求在阻断时仍返回统一 `202` 且不查询身份、不触发投递；
- Agent Run 的 `UNKNOWN` 不再按 15 分钟自动释放并发，而是在可信对账改变状态前始终占槽；生成上下文改为保守 UTF-8 预算化组装，固定保留系统提示词和当前问题，先加入检索知识，再按由新到旧加入历史。该估算器不是模型 tokenizer，Runtime 仍保留独立的最终输入 backstop；
- API 开发 watch 改用 `.nest-dev`，生产构建继续使用 `dist`，并新增隔离回归验证生产构建期间影子 watch 保持健康，避免 `dist` 清理导致开发 API 被终止；
- 变更前已运行的旧 watch 进程不会在运行中自动切换输出目录，需要等下次正常启动后生效。为遵守不中断现有开发服务的约束，本批没有手动重启该进程；
- 新增默认离线的语义验收工具回归；离线模式验证数据集结构、覆盖规则、网络门禁与报告逻辑，不访问数据库、部署服务或外部供应商，也不计算真实检索质量；
- 修复指定 Embedding 模型在零知识切片上的空集合误判：此时顶层状态为 `not_ready`、语义状态为 `insufficient_evidence`、退出码为 `2`，并返回 `KNOWLEDGE_EMBEDDING_EVIDENCE_EMPTY`；
- 恢复门禁改为逐项精确验证 31 张租户表的 `ENABLE/FORCE RLS` 与 restrictive `FOR ALL` 策略矩阵、`auth_login_rate_limits` 特殊认证限流策略、action token 策略、表级与列级 ACL、约束和索引，以及 Agent Run 用量约束；另在事务内执行四个反向控制并回滚：关闭 `agent_runs` FORCE RLS、把租户策略弱化为 `OR true`、新增未登记的 `tenant_id` 公共表、关闭认证限流表 FORCE RLS；
- 恢复目标名限制为不超过 63 字符的 ASCII 标识；临时库通过创建时记录的数据库 OID 与 GUID comment 共同确认身份，只清理自身创建且身份匹配的目标，目标已存在时除非显式允许替换否则拒绝覆盖。

### 当前仍为 No-Go 的发布门禁

1. 必须使用非空、脱敏的真实企业问题集，连接真实 Embedding 与 Reranker 供应商，完成 Recall@5、nDCG@10、MRR、无答案准确率、P95 延迟及 ACL 泄漏为零的联网验收。27 项离线工具回归只证明验收器自身行为，不能替代供应商或语义效果验收。
2. 忘记密码与成员邀请的 API、令牌状态和管理界面已实现，但邮件发送仍是非持久化 best-effort 路径；生产邮件投递需要 durable Outbox、领取/重试、进程恢复和投递告警闭环。
3. 仍缺覆盖生成、Embedding 与 Reranker 的统一用量账本，以及不可变模型价格版本、币种和部门预算；现有 Agent Run 可信上报统计不能被描述为完整 AI 成本核算。
4. 仓库内已有一次性运维脚本和 Windows 计划任务注册器，但尚未在生产机器上以 `SYSTEM` 实际注册并验证文件、容器和网络权限；告警通道和值班系统尚未接线，备份尚未进入加密异地/不可变存储。这些代码与离线测试不能替代生产部署验收。
5. Manus 停止接口能够执行确认式取消；通用 OpenAI-compatible Chat Completions 没有标准取消资源。生产供应商若没有可确认取消协议，仍不满足“停止生成”发布门禁。
6. AI Runtime 当前只有开发用内存 RunStore，生产启动会明确拒绝该配置，而 PostgreSQL RunStore、服务间认证与多实例执行租约尚未实现；因此现有 130 项 Runtime 回归不等同于可重启、可横向扩展的生产运行链路。

因此第三批复验后的结论仍是 **V1 No-Go**。账号恢复与邀请的产品链路已经落地，但只有真实语义问题集、生产运维接线/异地备份、可恢复邮件投递和统一用量治理完成后，才可进入 20～100 人真实试点。
