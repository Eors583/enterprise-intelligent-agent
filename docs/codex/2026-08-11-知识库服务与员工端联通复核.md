# 知识库服务与员工端联通复核

复核时间：2026-08-11（Asia/Shanghai）

## 结论

- 当前本地开发环境中，API、AI Runtime、管理后台、Electron 员工端、PostgreSQL/pgvector、Redis、Qdrant、MinIO、Docling 和 ClamAV 均已运行，知识测试必要服务齐全。
- API `GET /health/ready` 返回 `ready`，Prisma repository 与 AI Runtime 均为 `up`。开发环境的 `knowledgeIngestion=not_required` 是就绪探针语义，不表示入库能力停止；当前入库 Worker 开关已启用。
- AI Runtime `GET /health/ready` 返回 `ready`，Embedding 与 Reranker 均为 `ready`。Telemetry 在开发环境未接入，不阻断知识检索。
- 员工端没有独立知识库。个人智能体使用 `owner-authorized` 范围，每次 Agent Run 通过 `KnowledgeRetrievalGateway.resolveAccessibleKnowledgeBaseIds` 根据当前租户、提问用户、组织归属、知识库范围和文档范围动态解析后台知识，不保存员工端副本。

## 当前数据与索引

- 当前登录的“未来协作科技”租户有 2 个启用的后台知识库：“企业知识库验收 msfgv4n8”和“知识库文件导入验证 知识库”。它们都是管理后台中的有效业务知识库，不是员工端重复库。
- Qdrant 当前有共享/旧版索引 collection 与按知识库、索引版本和维度创建的新 collection。两者均仍有活动索引数据，是存储实现细节，不是两套业务知识库；本次未删除任何 collection。
- “蓝血研究”租户的 Claude Code 资料属于另一个租户。它与“未来协作科技”员工端使用同一套 Knowledge Gateway 和存储服务，但租户边界会阻止林晓跨租户检索该资料。

## 实际验收

- 管理后台使用当前管理员权限执行真实检索，查询“企业知识库应该如何存储和检索文档？”命中《企业级知识库搭建指南》3 个切片，结果包含知识库、文档、版本、章节和相关度，用时约 4.9 秒。
- 管理后台对第二个知识库查询验收口令，命中唯一正确切片，用时约 269 毫秒。
- 公共 Conversation/Agent Run 链路的真实运行成功，返回了后台知识库文档的 `LINEAGE_VERIFIED` 引用。请求员工重新打开引用返回 HTTP 200，另一名成员使用同一 message/version/chunk 访问返回 HTTP 404，说明引用回读权限会实时复核。
- 本轮同一验收问题的一次 Agent Run 虽然状态为 `SUCCEEDED` 且返回了另一后台知识库的可核验引用，但未命中期望的口令文档。因此可确认“链路已联通”，但不应将单次跨两个知识库的召回精度误报为 100%。

## 数据安全提醒

复核索引时发现“蓝血研究”租户有一篇账号类表格文档包含访问凭据，且已进入切片和向量索引。凭据类文档不应作为 RAG 知识源；建议通过正式知识管理 API 删除该文档，并立即轮换其中所有凭据。本次不将该业务文档自行当作“多余知识库”删除，避免在用户未确认具体文档时误删数据。
