# 飞书成员登录邮箱本地覆盖实施与验收

## 背景与目标

飞书通讯录成员不一定提供可用于企业系统登录的邮箱。原实现为这类成员生成
`feishu-…@external.invalid` 占位地址，以满足内部用户记录的唯一性约束；管理端又将飞书成员字段整体视为目录托管，导致管理员无法替换占位邮箱，也无法用真实邮箱完成邀请、密码恢复和登录。

本次目标是把“目录身份”和“本地登录身份”分开治理：姓名、部门、职位、在职状态继续由飞书管理，真实登录邮箱和企业角色由本系统维护，并保证邮箱修改、邀请激活、登录、找回密码、MFA、离职停用和后续飞书同步形成一致且可审计的闭环。

## 已实现设计

### 管理端

- 飞书成员管理弹窗新增始终可编辑、必填的“登录邮箱”。
- 飞书托管的姓名、部门、职位和账号状态仍为只读，避免本地修改被下一次同步覆盖。
- `@external.invalid` 占位邮箱会阻止发送或重发邀请，并提示先保存真实邮箱。
- 邮箱存在未保存修改时，邀请、重发邀请和密码重置均暂时禁用，避免操作使用旧地址。
- 保存真实邮箱后，邀请入口恢复；历史投递地址若来自迁移推断，会明确标记并提示不能当作精确投递凭证。

### 身份与登录

- 保存邮箱时，同时更新租户内的 `User.email/emailNormalized` 和该成员全部未终止任职记录的 `Employment.workEmail`。
- 飞书成员的任职记录标记 `workEmailOverridden=true`，新部门关系也继承该本地邮箱。
- 邮箱在当前租户内不得与其他用户主邮箱或其他未终止任职邮箱冲突。
- `@external.invalid` 被限定为内部占位域，不能用于登录、找回密码或邀请投递。
- 邮箱修改使用与登录、邀请、找回密码相同的 password-flow advisory lock；修改成功会撤销该成员的活跃会话和全部未消费身份令牌。
- 普通登录、密码找回和 MFA 完成阶段都会在锁内重新验证当前邮箱、用户状态、租户状态和凭据，旧邮箱不能利用并发窗口创建新会话或找回令牌。

### 飞书同步与离职治理

- 飞书同步不会覆盖本地登录邮箱；新增部门任职也继承同一邮箱和覆盖标记。
- 同步预览不再把远端邮箱变化误报为本地覆盖更新。
- 若远端邮箱或历史本地覆盖邮箱已被另一用户占用，预览标记 `USER_EMAIL_CONFLICT`，正式同步拒绝写入，避免两个账号同时拥有同一登录别名。
- 飞书停用或移除成员时，系统取得相同身份锁，并撤销会话、邀请和找回令牌；旧邀请不能把离职账号重新激活。

### 投递证据与数据库治理

- `AuthActionToken` 保存不可变的 `deliveryTargetEmail`，以及 `ISSUED` 或 `LEGACY_INFERRED` 证据类型。
- 历史数据回填值明确标记为 `LEGACY_INFERRED`，不会伪装成真实历史投递证明。
- 数据库触发器禁止修改已写入的投递目标及证据类型；恢复门禁同时校验 CHECK、触发器、函数定义、固定 `search_path` 和最小 ACL。
- 当前开发库曾在开发过程中以旧迁移名应用相同 SQL。核对确认旧记录与最终迁移文件 SHA-256 完全一致，列、约束、触发器、函数、ACL 和数据不变量全部存在后，使用 Prisma `migrate resolve --applied` 对齐新迁移名；未删除或重写任何业务数据。当前 `prisma migrate status` 为 up to date。

## 管理员使用流程

1. 进入“组织与成员 → 成员”，打开带“飞书”标签的成员。
2. 在“登录邮箱”填写真实且未被其他成员使用的邮箱，点击“保存成员设置”。
3. 如果该成员已有密码凭据，原密码仍有效，但旧会话会退出；成员应使用新邮箱重新登录。
4. 如果该成员尚未激活登录身份，重新打开成员弹窗并点击“发送一次性邀请”。成员通过一次性链接设置自己的密码后，即可使用企业标识、真实邮箱和新密码登录。
5. 若邮件服务未配置，管理端只在本次操作中显示短期一次性邀请链接，管理员需通过安全渠道交付。

## 边界与后续

- 修改邮箱不会为从未激活的飞书成员自动生成共享密码；该成员必须接受一次性邀请、使用已配置的企业 SSO，或由管理员按受控流程重置密码。
- 飞书仍是姓名、组织和在职状态的权威数据源；登录邮箱一旦由管理员保存，则成为租户本地身份数据，不再跟随飞书邮箱变化。
- 独立复验库已保留，未访问或修改 `enterprise_agent_acceptance` 与 `enterprise_agent_vector_acceptance`。
