# 知识入库三类异常诊断与修复

## 现场结论

- `DOCUMENT_PARSER_INVALID_RESPONSE`：主要来自复杂 PPTX。Docling 在批量负载中累计重启 42 次，连接中断或响应不完整；不能据此判断源文件损坏。
- `KNOWLEDGE_FILE_SCAN_UNAVAILABLE`：ClamAV 服务健康，但批量扫描时持续满核，原 30 秒时限不足以稳定覆盖约 50MB 文件。
- `KNOWLEDGE_INGESTION_FAILED`：实际包含 MinIO 连接重置和 PostgreSQL 默认 5 秒交互事务超时。旧日志只记录异常类型，无法区分真实原因。

## 修复

- Docling 仍是 PPTX 主解析器；仅当其超时、不可用或响应无效时，复用已有 Apache Tika 做文本提取降级。
- ClamAV 扫描时限从 30 秒调整为 90 秒，仍小于 120 秒入库租约；安全扫描失败仍不得绕过。
- 租户事务默认时限调整为 30 秒，保留事务原子性、租约校验和失败不发布语义。
- Worker 记录任务 ID、异常类型及经过控制字符清理和长度限制的错误摘要，不记录文档内容或凭据。

## 验证边界

- Tika PPT/PPTX 适配器和 Worker 回归测试通过。
- API 类型检查与生产构建通过。
- 真实 Tika、ClamAV、MinIO、Docling、PostgreSQL 容器均处于运行状态。
- 失败任务继续按现有有界退避处理；历史已失败任务仍需由用户点击重试或通过正式管理接口重新排队。
