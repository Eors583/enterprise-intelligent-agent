# 企业知识库 Qdrant 与复杂文档验收

## 目标与范围

本轮按《企业级知识库搭建指南》的文件型知识主链完成本地可运行实现，重点是先跑通“智能体 + 知识库”，不恢复会妨碍初版验证的发布审核和评测门禁。既有租户隔离、资源范围过滤、版本账本和引用二次校验仍然保留。

本轮验收范围是：原件保留、病毒扫描、复杂文档解析、统一结构化对象、切片、Embedding、Qdrant Dense/Sparse 混合召回、PostgreSQL 权威复核、关系扩展、Rerank、证据充分性检查、无依据拒答、管理端上传/预览/检索界面。

## 最终架构

```text
Admin 上传
  -> MinIO 原件（不可覆盖，独立 SHA-256 账本）
  -> ClamAV
  -> Docling：PDF / DOCX / XLSX / PPTX / 图片
     或本地解析：Markdown / Text
  -> MinIO *.structured.json（统一结构化表示）
  -> PostgreSQL：文档、版本、父子/相邻切片、权限、关系和审计事实
  -> AI Runtime：本地 BGE Embedding / Reranker
  -> Qdrant：Dense + Sparse + RRF 候选索引
  -> PostgreSQL：按租户、发布版本、文档状态和资源策略复核候选 ID
  -> 加权融合 / Cross Encoder / 关系证据 / 充分性过滤
  -> XLSX 聚合问题：授权工作簿 -> 隔离 SQLite -> 参数化只读 SQL
  -> Agent Run 与管理端返回可追溯引用；证据不足时返回 noAnswer
```

Qdrant 不是权限或版本的权威来源。外部索引查询发生在 Prisma 事务之外，命中后只把 chunk ID 和分数带回 PostgreSQL；正文、当前版本和可访问性均以 PostgreSQL 为准。Qdrant 不可用时保留 pgvector 回退路径。

## 已实现能力

- 新增独立知识基础设施编排：MinIO、Qdrant、Docling Serve、ClamAV；不把大文件或主向量索引压在业务 PostgreSQL 上。
- MinIO 同时保存原文件和结构化 JSON；版本表记录两类对象的 key、长度、SHA-256 和结构化格式。
- 引用接口按当前授权下载原件；Electron 使用系统默认程序打开临时原件，页面同时显示页码、章节或工作表定位。
- Docling 接入 PDF、DOCX、XLSX、PPTX 和常见图片，保留 Docling 文档对象、Markdown、页/表格结构和 parser provenance；Markdown/Text 使用本地解析器并生成同一结构化 envelope。
- Qdrant collection 使用 1536 维 Dense 向量和 Sparse 词项向量；发布、重建和归档与版本生命周期同步。
- PostgreSQL 显式保存父块、子块、父级 ID 和前后相邻 ID；检索可从精确子块扩展到完整章节或表格上下文。
- 检索支持知识库级 HYBRID/VECTOR/FULL_TEXT、TopK、最低分数、语义/关键词权重、Rerank 开关、关系开关和单文档切片上限。
- 关系 SQL 通过 materialized CTE 限制候选范围；只有直接实体种子产生的关系证据可以单独通过充分性检查，避免无关向量种子被关系分数放大。
- Cross Encoder 在当前本地 CPU 基线中精排融合后的前 3 个候选，召回指标仍按更大的混合候选集合计算；模型对表格全部低分时保留可解释的混合召回排序，同时仍执行直接证据过滤。该数量是本次 200 题延迟/质量评测后的部署参数，不是不可调整的通用常数。
- 无答案判断不再只看融合分。候选必须具备可靠 Rerank、足够直接词项/模糊证据、直接中文词项或直接实体关系证据之一；纯“语义相近”不能进入回答上下文。
- XLSX 精确查询支持值、求和、平均、最大/最小、计数、同比和环比；当前从已授权工作簿装载隔离的进程内 SQLite，执行参数化只读 SQL。
- 管理端支持多格式上传、重复/版本预检、文档/版本状态、索引就绪诊断、可读结构化预览、答案优先检索、关系证据、原件打开和无依据拒答提示。
- Agent Run 已使用同一检索服务，知识范围写入运行快照，输出引用仍需通过发布版本、内容哈希和资源范围二次校验。
