# 知识库大文件与重复向量化优化

日期：2026-08-12

## 已实现

- 管理端取消 100MB 产品上传限制。共享契约、API 接收、对象存储客户端、病毒扫描客户端和文档解析器统一使用 `2,147,483,647` 字节的基础设施上限。
- 开发环境 ClamAV 的流、单文件和扫描总量上限同步为 `2047M`，避免文件通过 API 后在安全扫描阶段被旧的 100MB 配置拒绝。
- 上传前端和后端均计算文件 SHA-256。相同知识库、相同目录（或同一文档的新版本）中已有相同 SHA-256 且状态为 `READY` 的版本时，直接返回现有文档，复用其切片和向量，不创建新的入库任务，也不再次调用 Embedding。
- 失败、处理中或已删除的版本不会被当成可复用版本，用户仍可重新上传或重试。

## 技术边界

当前约 2GB 上限不是产品套餐限制，而是 PostgreSQL `object_size` 整数字段和 NestJS 内存上传链路的技术边界。需要稳定接收数 GB 文件时，应改为对象存储预签名分片上传，上传完成后再通过 Knowledge Gateway 登记入库，不能继续扩大 API 进程内 Buffer。

重复复用按租户、知识库和目录边界执行，避免跨权限边界泄露“某个文件已经存在”。不同目录需要分别显示同名资料时仍保留独立文档语义；若要跨目录复用底层内容，应增加“内容资产—文档引用”模型，不能让一个目录上传静默指向另一个目录而破坏目录树。

## 中断后派生成果冲突恢复

Worker 在解析完成后会写入结构化 JSON，再提交切片、向量和版本状态。进程中断可能留下尚未登记到数据库的结构化派生成果。后续重试如果得到不同字节，原有不可变对象保护会返回 `KNOWLEDGE_OBJECT_CONFLICT`。

现在只对这一明确场景做针对性恢复：当前任务仍持有租约时，清理同文档版本的残留结构化派生成果并重新写入一次，然后继续切片。原始源文件仍不可覆盖；源文件哈希冲突、失去租约、权限异常和真实解析失败不会使用该恢复分支，也不会无限重试。
