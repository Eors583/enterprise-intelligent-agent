# 知识库文件夹上传与 100MB 文件支持

## 目标

企业资料可以按本地文件夹递归导入，并在一个知识库内部保留真实目录层级；单文件接收、扫描和解析上限由 20 MB 提升到 100 MB。

2026-08-11 补充：新版 `.pptx` 继续由 Docling 解析；旧版 `.ppt` 是 OLE2 二进制格式，新增 Apache Tika 3 + POI 专用解析链路，不用修改后缀或伪装成 `.pptx`。两类格式解析后都进入同一份知识文档账本、对象存储、切片、向量化、权限过滤和检索索引。

## 已实现设计

- 新增 `knowledge_folders`，通过 `tenant_id + knowledge_base_id + path` 唯一约束保存目录；父子目录使用稳定 ID 建树。
- `knowledge_documents.folder_id` 指向知识目录，根目录文档保持 `NULL`，不复制文件或对象存储数据。
- 目录表启用并强制 RLS；创建目录必须经过知识管理 API 和管理员写权限，并记录审计事件。
- 公共契约返回目录清单以及文档的 `folderId`、`folderPath`。前端不访问 Prisma、对象存储或 Qdrant。
- `POST /admin/knowledge-bases/:id/folders/ensure` 幂等创建路径及缺失的父目录，最多一次提交 1,000 条路径、最多 20 层；管理端自动分批，可一次选择最多 10,000 个文件。
- 浏览器通过 `webkitdirectory` 读取相对路径，先建立目录，再把每个文件交给现有的重复检查、安全扫描、对象存储、解析、切片和索引链路。
- 同名文件只在同一目录内被判断为新版本；相同内容会跳过，单个文件失败不阻断整批其余文件。
- 浏览器不能返回空目录，因此提供独立“新建文件夹”按钮，支持建立空目录或补齐目录结构。
- 单文件上限在共享契约、管理端校验、NestJS Multer、ClamAV 客户端、ClamAV 服务和文档解析器统一为 100 MB。
- 单文件、批量导入和文件夹导入均接受 `.ppt` / `application/vnd.ms-powerpoint`；API 会验证 OLE2 文件签名，再通过受超时和响应大小约束的 Tika 适配器抽取文本。
- 文件夹批量上传完成后，重复、空文件、格式不支持和超限文件进入“被跳过”清单；网络、目录创建或 API 上传异常进入“上传失败”清单，并可只重新上传失败项，已成功文件不会重复提交。
- 文件夹目录卡片递归汇总当前文件夹及全部子目录的最新文档版本，展示“切片与索引”百分比、完成文档数、已生成切片数、处理中数量和异常数量。处理中时沿用知识页面已有的 3 秒轮询刷新；点击异常文件夹后可逐层进入并定位失败文档，再使用文档级重试。

文件夹百分比以知识公共 DTO 中的真实入库任务为依据，不新增第二份进度账本：READY 文档计 100%，PROCESSING 文档使用 `ingestionJob.progress`，FAILED 和尚未开始的文档计 0%，最后按文件数求平均并四舍五入。父文件夹按 `folderPath` 前缀包含所有后代文档；已删除文档不参与统计。

## 使用流程

1. 进入知识库的“文档管理”。
2. 点击“导入文件夹”，选择企业资料根目录。
3. 确认文件数、目录数、跳过项并开始上传。
4. 上传完成后通过面包屑和文件夹卡片浏览层级；文档继续异步完成解析和索引。
5. 如需空目录，在目标目录内点击“新建文件夹”。

## 边界与后续生产优化

- 当前采用逐文件、有限范围的客户端编排，失败可定位到具体文件，并复用现有治理链路。
- 100 MB 文件当前仍由 NestJS 进程内的 Multer memory storage 接收。开发环境可验证功能；生产大并发建议升级为对象存储预签名分片上传、异步登记与断点续传，避免多个 100 MB 文件同时占用 API 内存。
- 浏览器目录选择不包含空目录，这是 Web File API 限制，已由“新建文件夹”补足。
- 本次目录只承担组织和浏览，不改变知识库及文档权限继承、检索范围、引用版本和对象存储键的安全边界。
