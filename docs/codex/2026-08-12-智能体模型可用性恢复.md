# 智能体模型可用性恢复

## 现象

员工端向智能体发送消息时被拦截，提示已启用目标智能体，但尚未取得经过验证的模型可用性证据。

## 根因

模型与 AI Runtime 实际可连接，但受控模型连通性检测在准备智能体上下文时失败。知识入库负载下，租户事务超过 Prisma 默认 5 秒交互式事务时限；检测尚未调用模型便被中止。准备异常同时被错误标记为 `UNKNOWN`，造成后续检测被当作待对账任务阻塞。

## 修复

- 智能体准备快照事务使用受控的 30 秒时限；外部知识检索仍在事务之外执行。
- 没有选定知识库时跳过无意义的知识检索。
- 受控模型连通性检测明确使用空知识范围，只验证模型链路，不加载企业知识。
- 模型调用前的准备失败标记为 `FAILED`，不再错误占用需要供应商对账的 `UNKNOWN` 状态。
- 增加脱敏后的准备失败日志及回归测试；真正发生不确定外部调用的情况仍保持 `UNKNOWN` 和人工对账边界。

## 实际验证

- AI Runtime 就绪，模型、Embedding 与 Reranker 依赖检查通过。
- 受控真实模型检测成功：状态 `SUCCEEDED`，证据状态 `VERIFIED`。
- 管理端模型路由状态为 `READY`，近期成功候选数为 1，熔断状态为关闭。
- API 类型检查和生产构建通过。
- API 全量测试：1,360 项通过、155 项跳过。
- 相关回归测试：2 个文件、18 项全部通过。

## 尚未验证

已验证真实模型与后端运行链路；尚未代替截图中的具体员工账号在 Electron 界面完成一次人工发送与回答阅读。该账号可以直接使用原消息重试，服务端模型可用性拦截条件已解除。

## 2026-08-17 单一企业所有者发布模型治理版本

真实租户 `lxyj` 只有一名企业所有者，原有模型目录和路由策略强制不同账号提交与发布，导致单管理员企业无法完成首次模型接入。规则调整为：企业 `OWNER` 可以提交并发布自己负责的模型目录或路由策略；受委托的 `ADMIN` 自行提交后仍须由另一名管理员发布。发布仍保留草稿、提交、发布、修订号 CAS、完整审核字段、审计、Outbox、Runtime 精确允许列表和真实连通性证据。

前向 migration 仅解除数据库对“提交人与发布人必须不同”的硬编码约束，继续强制发布版本具有提交、审核和发布时间。应用服务根据可信会话角色执行 OWNER 例外，普通管理员不能借此自行改变模型供应商、数据分级或外发路由。

## 2026-08-19 智能体对话入口始终可用

产品规则调整为：已启用且当前用户有权使用的智能体，其通讯录、搜索、新建会话、群聊和消息入口不再以模型就绪度作为禁用条件。模型路由、供应商或近期成功证据暂未就绪时，仍允许创建会话、发送消息并尝试真实运行；失败由该次 Agent Run 保存明确错误和重试入口，不再把智能体入口整体置灰。

显式停用或离线的智能体、已离职成员、未授权指派、跨租户访问和知识权限过滤仍继续拒绝。模型就绪度仍用于后台诊断、状态展示、熔断和运维，不再充当员工对话入口开关。
