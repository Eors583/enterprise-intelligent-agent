# 知识库独立业务边界红线实施记录

日期：2026-08-06

## 结论

本次将“知识库独立业务边界”从口头约定提升为代码依赖规则、版本化事件契约、CI 架构测试和 ADR。业务模块只能使用 Knowledge Gateway；管理端和第三方只能使用知识公共 API；异步消费者只能使用正式事件协议。

## 已处理的越界点

- 管理概览不再通过原始 SQL 汇总知识表，改读 Gateway 运营摘要。
- AI 评测不再读取文档版本、切片、向量、图谱和本体表，改读 Gateway 的不透明评测快照与受治理语料。
- 经验候选投影不再直接驱动知识入库实现或读取知识物化状态，改用 Gateway 命令和只读投影。
- Agent Run 不再携带 Prisma transaction 进入知识端口，证据复核由 Gateway 自己完成。
- 智能体知识绑定、角色蓝图知识范围、组织单元删除校验和飞书目录同步改用 Gateway 校验/计数能力。
- 外部 knowledge smoke 工具删除 Qdrant collection 直连，只通过知识公共 API 检查 readiness。
- 删除未使用且会直读知识表的 Agent Run legacy loader。

## 自动守卫

新增 `apps/api/src/modules/knowledge-gateway/knowledge-boundary.architecture.spec.ts`：

1. 边界外生产代码不得导入知识内部模块。
2. 边界外生产代码不得调用 Prisma 知识模型或知识原始 SQL。
3. 边界外代码和外部冒烟工具不得直连 Qdrant 或知识对象存储。
4. Gateway 公共端口不得引用 Prisma transaction 或知识内部实现类型。
5. 知识边界的临时 `admin/` 所有权采用逐文件白名单；扩大白名单必须先更新 ADR。

## 正式事件

新增共享合同 `packages/contracts/src/knowledge-events.ts`。解析审核、治理更新、治理审核、文档版本发布、来源同步成功/失败事件在写入 Outbox 前通过 Zod 校验。已有 `.v1` 事件未来不能原地改变字段语义，破坏性修改必须发布新版本。

## 当前边界强度

当前已具备代码依赖和 CI 层硬约束，但 NestJS API 仍是同进程部署，并共用数据库连接身份。因此它还不是生产网络层和数据库账号层的物理隔离。生产服务化时还必须给知识数据库、Qdrant、S3/MinIO 配置独立服务身份，并撤销业务 API 身份对这些资源的直接权限。具体决策见 `docs/adr/0008-knowledge-independent-business-boundary.md`。
