# 后台成员添加与员工本人个人使用说明书实施记录

日期：2026-08-10

## 1. 本次目标

在企业管理后台提供不依赖飞书的原生成员添加入口，只由管理员维护成员基础资料、工作信息和上下级关系。个人使用说明书属于员工本人，不属于管理员代录资料；唯一写入入口位于员工端“我的”。飞书仍可作为外部通讯录来源，但不再是录入企业成员的前提。

## 2. 用户流程

管理员进入“组织与成员 → 成员”，点击唯一的“添加成员”按钮，在同一个表单内填写：

1. 基础信息：姓名、部门、手机号、工作邮箱、头像链接和员工编号。
2. 工作信息：人员类型、入职日期、工作国家或地区、工作城市、直属上级、虚线上级、职务和企业角色。
3. 提交后创建一次性邀请，由成员通过邀请设置自己的密码；后台不要求管理员代成员设置初始密码，也不允许管理员代填个人使用说明书。

成员接受邀请并登录员工端后，从“我的 → 个人使用说明书”填写个人简介、教育背景、职业经历、岗位职责、沟通偏好、协作习惯、常规安排、联系信息、核心技能、可提供资源、兴趣爱好、参加社团和常见问答。

人员类型支持：正式、实习、外包、劳务、顾问。

## 3. 数据归属

| 数据                                                       | 数据表/模型                             | 说明                                    |
| ---------------------------------------------------------- | --------------------------------------- | --------------------------------------- |
| 姓名、手机号、工作邮箱、头像                               | `users` / `User`                        | 成员账号与基本身份资料                  |
| 部门、职务、员工编号、人员类型、入职日期、国家或地区、城市 | `employments` / `Employment`            | 成员在当前企业中的任职资料              |
| 直属上级、虚线上级                                         | `manager_relations` / `ManagerRelation` | 分别以 `DIRECT`、`DOTTED_LINE` 关系保存 |
| 个人简介至常见问答                                         | `member_profiles` / `MemberProfile`     | 当前登录成员本人通过自助接口维护        |

`member_profiles` 使用租户复合外键、唯一约束和行级安全策略。管理员创建成员时不会创建或更新该表；自助接口不接受目标用户 ID，只使用当前认证会话中的 `tenantId` 和 `userId`。管理服务仍统一校验上级必须是当前企业的在职成员，不能通过请求写入其他企业的用户关系。

## 4. 数据库迁移

- `20260810000100_member_directory_profile`：增加 `employments.country_or_region`，创建 `member_profiles`、索引、租户隔离策略和最小数据库权限。
- `20260810000200_member_manager_admin_access`：为后台服务身份补齐 `manager_relations` 的受控读写权限和租户策略。
- `20260811000100_member_profile_self_service`：为员工应用身份增加本人 `INSERT/UPDATE` 策略，写入必须满足 `user_id = app.user_id`。
- `20260811000200_member_profile_self_owned`：撤销后台管理员服务身份对 `member_profiles` 的新增、更新和删除权限，只保留租户内读取能力。

两项迁移均已应用到当前本地开发数据库，并通过 Prisma schema 校验。第二项迁移同时修复了组织成员页面读取上下级关系时的数据库 `permission denied for table manager_relations` 错误。

## 5. 契约和后端行为

- 管理端共享 Zod 契约只定义五种人员类型和直属/虚线上级等成员入职字段，不再接受或返回个人说明书。
- 个人说明书使用独立的本人自助契约，包含六部分内容和动态常见问答。
- 创建成员与发送邀请共用同一套录入字段和“直属上级不能等于虚线上级”校验。
- 成员创建、任职创建和上下级关系创建在同一个数据库事务中完成，不触碰个人说明书。
- 即使旧客户端向管理员接口附带 `personalManual`，契约解析也会丢弃该字段，服务层没有对应写入路径，数据库管理员角色同样没有写权限。
- 新成员使用现有一次性邀请机制设置密码，管理员不会看到或保存成员的初始密码。

## 6. 管理后台和样式规范

- 页面只保留一个“添加成员”主操作，不使用“高级”折叠入口，也不展示“使用初始密码建号”。
- 后台添加成员表单只按“基础信息、工作信息”分组，并提示成员登录员工端后自行完善个人使用说明书。
- 大屏使用双列布局，小屏自动变为单列。
- 字体、颜色、间距、圆角、边框和控件尺寸均引用管理后台设计 Token；成员录入表单规范已同步写入 `docs/design-system/admin-ui-style-spec.md`。

## 8. 当前边界与后续项

本次完成的是“管理员新增成员 + 员工本人完善说明书”边界。头像沿用现有 `avatarUrl` 字段，当前由组织档案填写图片链接，尚未增加本地图片上传和对象存储链路。已有成员“管理”弹窗不会扩展为编辑个人使用说明书；后续若增加头像上传，应独立处理身份头像，不改变个人说明书的本人写入原则。

邮件能否送达真实收件箱仍取决于部署环境的邮件服务配置；本地验证覆盖了邀请记录创建和接口行为，没有向真实人员发送邀请。

## 9. 2026-08-11：员工端本人填写能力

员工桌面端“我的”提供个人使用说明书的唯一编辑入口。员工可以分多次完善以下六个部分：

1. 我是谁：个人简介、教育背景、职业经历。
2. 我的岗位职责是什么：当前职责、工作边界和管理团队说明。
3. 怎样与我高效协同：沟通偏好、协作习惯、常规安排和其他工作联系方式。
4. 如何用好我、我还能提供哪些资源：核心技能和可提供资源。
5. 我有哪些兴趣爱好：兴趣爱好和参加的社团。
6. 您可能会问这些问题：最多 20 组可动态增删的常见问题与回答。

姓名、头像、部门和岗位继续以企业组织档案为准，在员工端只读展示；员工不能借填写说明书修改正式身份、任职或权限。说明书提供六部分完成度、分段填写状态、未保存提示、字符数量、保存反馈和并发编辑冲突提示。头像地址失效时自动降级为姓名头像，不显示破图。

## 10. 员工端数据与权限边界

- 只有员工本人自助填写会写入 `member_profiles`；后台成员添加和管理接口不会写入该表，也没有创建另一份个人知识或孤立资料表。
- 公共接口为 `GET/PUT /api/v1/workbench/people/me/personal-manual`，不接受用户 ID；服务端只从当前认证会话取得 `tenantId` 和 `userId`。
- `PUT` 使用 `expectedUpdatedAt` 做乐观并发控制，避免两个窗口互相覆盖；写入成功后记录审计和 Outbox，但审计元数据只保存填写项数量与 FAQ 数量，不复制个人正文。
- 数据库迁移 `20260811000100_member_profile_self_service` 只为应用身份增加 `member_profiles` 的 `INSERT/UPDATE`，RLS 的 `WITH CHECK/USING` 同时要求 `user_id = app.user_id`；后续迁移 `20260811000200_member_profile_self_owned` 撤销管理员服务身份的写权限。
- Electron 主进程只允许上述精确路径的 `GET/PUT`，渲染进程不能借通用代理请求其他成员的资料。
