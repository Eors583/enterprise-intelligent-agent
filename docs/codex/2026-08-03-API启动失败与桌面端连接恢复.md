# API 启动失败与桌面端连接恢复

## 现象

桌面端显示“暂时无法连接企业服务”。检查时 4173、5173、8100 正常监听，但 API 的 3000 端口没有监听。Nest watch 进程仍存在，实际应用子进程已退出。

## 根因与证据

API watch 编译被以下 TypeScript 错误阻断：

- `role-blueprint-admin.service.ts` 中知识范围解析结果未向类型系统保证必需的 `knowledgeBaseIds`。
- 对应测试构造的创建草稿请求使用了空对象作为 `knowledgeScope`，不满足当前规范化请求类型。

这导致 Nest watch 只保留监视进程、没有可监听 3000 端口的应用进程，桌面端 bootstrap 和后续同步请求因此失败。

## 修复

- `parseKnowledgeScope` 现在显式返回 `Record<string, unknown> & { knowledgeBaseIds: string[] }`。
- 解析失败时返回空的知识库 ID 数组；解析成功时同样规范化并保证该字段存在。
- 回归测试的草稿请求补充 `knowledgeBaseIds: []`，与服务端契约一致。

## 验证

- API TypeScript 类型检查通过。
- Role Blueprint Admin Service：11/11 测试通过。
- Nest production build 通过。
- `GET /health/live` 返回 HTTP 200。
- `GET /health/ready` 返回 HTTP 200；数据库、AI Runtime、知识入库、工具执行和飞书同步检查均正常或按配置就绪。
- 真实 Electron 窗口重新请求后，组织树、会话列表和消息区的“自动同步暂时中断”提示消失。

## 边界

- OpenTelemetry 当前为 `disabled`，与本次连接故障无关。
- 本次没有停止桌面端、管理端或 AI Runtime 服务；API watch 在编译修复后自行恢复应用子进程。
