# 企业知识库非技术用户体验审计

日期：2026-08-05
对照文档：`C:\Users\PC\Documents\企业级知识库搭建指南.md`
体验对象：真实管理后台、真实 API/数据库/对象存储/向量库、真实 Electron 员工端

## 结论

从不懂编程、也不了解 RAG 的管理员角度，当前初版已经可以完成：进入知识库、选择资料、识别重复或新版本、等待解析、查看可读表格和切片、用自然语言检索、获得答案与来源、打开原文件，以及在证据不足时看到明确拒答。

本轮已经修复首轮审计中最影响小白验证的问题：

- 新增上传前重复/版本检查；
- 新增显式父块、子块和相邻块展示；
- 结构化预览由原始 JSON 改为可读工作表/表格，JSON 收进高级详情；
- 检索页先显示答案和来源，分数、内部 ID、阶段代码收进诊断；
- Excel 同比/环比问题进入参数化 SQL，而不是让模型估算；
- 无答案结论移到第一屏；
- 普通设置隐藏 TopK、阈值、权重和 Token 参数；
- 来源可以打开原文件，并显示页码、章节或工作表定位；
- 评测页支持 200～500 题导入、证据标注、异人审核、发布、真实逐题检索、服务端进度、失败保留和复测；
- 员工端历史回答不支持反馈时，改为中性中文说明并禁用按钮；新回答可以提交“有帮助/没帮助”、原因和补充说明；
- 新增面向企业文档源的 HTTPS Manifest 增量连接器，并在界面真实验证新增、更新、删除归档和游标推进；
- 员工“没帮助”反馈已经进入管理端坏例，完成归因、加入草稿数据集、创建回归用例和标注。

体验已经达到“可让非技术人员参加初版功能验证”的程度，但还不等于生产可用。200 道来源绑定技术基线已通过，本地受控文档源增量同步和反馈治理闭环也已跑通；应用内精确页码/工作表跳转、业务场景预设、真实网盘厂商 OAuth/服务账号和 ACL 投影、由业务部门提供的真实员工问题、生产身份和高可用仍需后续完成。

## 实际体验路径

### 1. 从业务概览进入知识库

![业务概览](../../.data/audits/2026-08-05-knowledge-novice-final/01-overview.png)

入口清晰，用户可以从业务概览看到知识健康并进入企业知识库。普通管理员无需先选择向量库或模型。

仍可改进：概览中的 P95、向量覆盖等词应增加通俗说明，例如“员工搜索是否够快”“资料是否已可被搜索”。

### 2. 查看知识库和资料

![知识库主页](../../.data/audits/2026-08-05-knowledge-novice-final/02-knowledge-home.png)

知识库、资料数量、状态和上传入口可直接找到。系统已将检索模式等工程信息降为辅助信息，但“上传资料”与“新建知识库并导入”的入口仍应进一步区分。

### 3. 上传时识别重复和新版本

![重复文件提示](../../.data/audits/2026-08-05-knowledge-novice-final/03-upload-duplicate.png)

系统在上传前计算文件哈希并查询现有资料：完全重复时阻止；同名但内容变化时允许选择新版本或独立资料。这个流程能防止小白用户因为多点一次按钮产生重复索引，同时保留不同业务身份的同内容模板。

仍可改进：同名新版本最好增加“有哪些变化”的摘要，并默认推荐“作为新版本”。

### 4. 查看父子块和原文位置

![父子块与相邻内容](../../.data/audits/2026-08-05-knowledge-novice-final/04-chunk-lineage.png)

页面能显示命中的子块、父级章节以及前后相邻内容，并显示页码/章节/工作表定位。用户无需理解 parent chunk ID；内部 ID 放在高级详情。

仍可改进：当前能打开原文件，但外部 PDF/Office 阅读器不保证自动跳到指定位置。生产体验应提供应用内预览器和稳定的深链接。

### 5. 首轮检索界面的主要问题

![首轮检索体验](../../.data/audits/2026-08-05-knowledge-novice-final/05-retrieval-before.png)

首轮界面把候选分数、Reranker、UUID 和阶段诊断放在答案之前。它适合开发排错，但会让普通用户不知道“系统到底回答了什么”。这成为本轮改版的主要依据。

### 6. 评测页形成可复现技术基线

![评测看板](../../.data/audits/2026-08-05-knowledge-novice-final/06-evaluation-dashboard.png)

旧截图记录了“没有数据就显示待评测”的初始诚实状态。随后已从真实前端创建检索专用版本，导入并标注 200 道来源绑定题，由资料负责人提交、另一位管理员审核发布，再实际逐题调用检索服务。页面显示真实服务端进度，最终指标卡为：Recall@5 100%、MRR 100%、nDCG@10 100%、来源支撑率 100%、无答案准确率 100%、P95 2496 ms、ACL 泄漏 0，状态“通过”。历史失败 Run 仍可追溯。

这批题是从已发布来源切片生成的技术验收基线，页面和本报告都不把它称为员工真实问题。下一步是让业务人员提供真实表达，并复用同一标注、审核、发布和复测流程。

### 7. 结构化 Excel 预览

![可读表格预览](../../.data/audits/2026-08-05-knowledge-novice-final/07-structured-table-after.png)

Excel 默认显示工作表和可读表格；原始结构化 JSON 只在高级详情中展开。业务人员可以核对行列和数值，不需要阅读 JSON。

仍可改进：增加冻结表头、搜索、较大表格分页和低置信单元格标记。

### 8. 答案优先、来源其次

![答案优先检索](../../.data/audits/2026-08-05-knowledge-novice-final/08-retrieval-answer-after.png)

改版后先展示直接答案，再列来源文件和定位；SQL、分数、候选数和阶段代码在可展开诊断中。真实 Excel 问题返回当前 99.9%、上期 99.7%、提高 0.2 个百分点。

仍可改进：把“可信度”改成更直观的“依据充分/依据有限”，避免用户把模型分数误解为统计概率。

### 9. 设置对普通管理员默认收起

![简化设置](../../.data/audits/2026-08-05-knowledge-novice-final/09-settings-simplified.png)

普通页面保留检索模式和精排开关；TopK、最低相关度、权重、切片大小和重叠量进入高级设置，降低误改风险。

仍需补齐：提供“制度合同、项目资料、表格数据”三类推荐配置和“一键恢复推荐值”。

### 10. 无答案先给结论

![无答案拒答](../../.data/audits/2026-08-05-knowledge-novice-final/10-no-answer.png)

当没有达到阈值且用户可访问的内容时，第一屏明确说明未找到依据，并说明不会拼接无依据回复。工程诊断放在后面，不再要求用户滚动查找最终结论。

### 11. 企业文档源增量同步

管理员可在知识库内创建受控 HTTPS Manifest 文档源并点击同步。真实本地 HTTPS 验收分两阶段执行：第一阶段新增 2 份资料；第二阶段新增 1 份、更新 1 份、删除归档 1 份，并把游标推进到 `fixture-phase-2`。更新后的差旅制度可以回答“国内差旅住宿标准现在是多少？”，结果为每晚 680 元；被删除的旧远程办公制度已经归档且不再进入当前检索。

这个界面使用“新增、更新、删除、跳过、失败”和“上次成功游标”等业务词，不要求管理员理解 webhook 或 ETL。当前连接器是通用 Manifest 协议；生产接入飞书、SharePoint、企业微信或其他网盘时，仍需由受控网关完成厂商 OAuth、续期、分页、限流和原始 ACL 到企业资源范围的映射。

## 员工端体验

真实 Electron 客户端已加载员工目录、智能体会话和消息。首轮检查发现，历史智能体回答的反馈接口返回英文 404 文本，普通员工无法理解。现在系统会识别“历史回答没有可评价记录”的情况：有帮助/没帮助按钮禁用，并显示“这条历史回答生成于反馈功能启用前，暂不支持评价”。

本轮还真实发送了一条员工消息，并对对应智能体回答选择“没帮助 → 缺少关键知识”，填写补充说明后提交。管理端立即出现不可变坏例，显示中文归因和反馈时间；资料负责人将它加入“员工反馈回归测试集”草稿版本，创建了预期为“证据不足时明确拒答”的回归用例并完成标注。坏例状态最终为“已加入数据集”。这证明前端操作、反馈持久化、坏例投影和数据集治理之间的基础闭环可用；尚未用真实员工规模和生产模型长期运营。

## 小白用户最可能遇到的困惑

1. **知识库和文件夹有什么区别**：首次进入应说明“知识库决定哪些资料一起被搜索”，而不是展示技术架构。
2. **上传后为什么不能马上提问**：用五阶段进度表示安全检查、解析、切分、建立索引、可用。
3. **为什么同名文件有两个选择**：默认推荐新版本，并解释“新版本会替代日常检索，但历史仍可追溯”。
4. **为什么来源能打开却没有自动跳页**：应在按钮旁明确提示当前阅读器能力，避免让用户以为定位失败。
5. **为什么有时显示加权排序**：普通模式无需展示；只在诊断里说明精排不可用时系统使用了可解释回退。
6. **技术基线和业务基线有什么区别**：页面明确说明“来源生成题”用于验证检索链路，只有业务部门提交的员工真实问题才能代表实际使用效果。
7. **关系图谱冲突是什么**：普通用户只需看到“冲突已处理完成”或待确认数量；本体、projection、predicate 等术语放在治理高级页。增量同步引入新关系类型后，已通过异人本体审核、批量修正审核和应用将开放冲突重新归零；当前 224 条活动关系均已治理，221 条进入已发布可检索读模型。

## 2026-08-06 主界面降噪调整

知识库详情已移除“实体关系”页签，只保留“文档管理、检索测试、知识库设置”。关系抽取、关系增强检索、就绪诊断和后端治理能力继续保留，不让普通管理员为了上传资料和验证回答而进入图谱管理界面。真实管理端复核确认“实体关系”入口为 0，“检索测试”和“知识库设置”均可正常打开，浏览器控制台无错误。

知识库前台同时将容易被非技术用户误解的“归档”统一改为“删除 / 已删除”。这里的删除是可追溯软删除：知识库或文档立即退出员工智能体检索，但历史文档、版本、引用和审计记录继续保留。删除确认框会在执行前明确说明这一后果，数据库状态和公共契约仍保持兼容的 `ARCHIVED`，不进行不可恢复的物理清除。

删除完成后，知识库和文档也会从普通知识库前端完全隐藏：不进入知识空间树、文档列表、搜索、状态筛选、数量角标和运行状态指标，不提供普通用户恢复入口。真实开发数据中原有 1 篇已删除文档，调整后列表和有效文档总数均从 9 变为 8，已删除文档标题、筛选项和指标的可见数量均为 0。底层记录只为审计、历史引用和后续合规处置保留。

删除知识库中的最后一篇有效文档时，系统现在会在同一数据库事务内同步软删除已经变空的知识库，因此右侧文档数量变为 0 后，左侧知识空间树不会继续残留一个无用容器。删除事务会先锁定所属知识库，再统计剩余有效文档，避免两篇文档并发删除时留下空知识库；历史上“曾经有文档、目前已无有效文档”的残留知识库由前向迁移统一修复。为避免误删管理员刚创建、尚未来得及上传资料的知识库，从未包含过文档的空知识库不会被这项历史修复处理。

“检索运行状态”不再固定展示在知识库所有页面顶部，而是收拢为独立的“运行状态”页签。文档管理、检索测试和知识库设置只展示各自任务内容；Embedding、Reranker、切片、语义覆盖和关系增强等诊断只在管理员主动进入运行状态时显示。诊断数据仍在后台加载，避免界面降噪影响文档发布和设置判断。

企业网盘与文档源不再以大卡片常驻文档列表，而是收拢为“其他来源接入”按钮。点击后弹窗直接加载已连接来源、同步状态和连接操作，不再要求用户在弹窗内二次展开；关闭弹窗后文档页不保留卡片、边距或空白。网页导入、文件上传和粘贴文本能力保持不变。

“更多录入方式”折叠入口已经移除，“粘贴文本”改为与导入网页、上传文件、其他来源接入并列的直接按钮。桌面内容区使用稳定两列标题栏，四个操作保持同一行；窄屏时统一纵向排列。真实页面确认点击粘贴文本后直接打开录入弹窗，不再多一次展开操作。

文档发布步骤也从普通用户流程中移除。文件上传、网页导入和粘贴文本统一采用“创建或上传 → 安全检查与解析 → 切片和索引 → 自动可用”的状态流；最新版本成功完成处理后，系统在同一事务内将它设为当前检索版本、激活对应关系投影并写入版本化发布事件。并发处理较旧版本完成时不会覆盖已经生效的较新版本。普通文档页的“发布 / 发布版本、查看切片、结构化预览、重建关系、重建向量、回滚到此版本”等开发或运维操作全部移除，版本记录只展示版本号、文件、切片数量、时间和是否为当前可用版本；处理失败时仍保留用户真正需要的“重试”。手工发布公共 API 暂时保留用于向后兼容和受控运维，但不再是初版用户的必经路径。前向迁移会自动接管升级前遗留的“READY 但未设为当前版本”文档；本地迁移完成后此类滞留文档计数已验证为 0。

知识库访问范围已经直接进入“上传知识文件”弹窗，不再要求管理员先离开上传流程、到另一个页面完成前置配置。管理员可以在选择文件时直接选择“全公司成员可访问”，或指定一个及多个部门、单独成员；部门范围默认包含下级部门，也可以取消。该范围是知识库级统一权限，服务端会在每次智能体检索前校验，因此会同时约束这个知识库中已有资料、本次文件和后续新版本，而不是只装饰当前文件。提交时系统先使用知识库版本号保存访问范围，保存成功后才上传文件并建立索引；若出现并发修改或保存失败，文件上传会中止，避免资料按旧权限进入系统。知识库设置页仍保留同一权限编辑器作为日后单独调整入口，但它不再是上传前必须经过的步骤。

文档列表新增“权限变更”入口，用于少数资料需要比所属知识库更严格的访问边界。默认仍继承知识库权限；管理员可以进一步限制到一个或多个部门、指定成员，部门与成员按“满足任一条件”计算，最终结果再与知识库权限取交集。因此文档权限只能收紧，不能把知识库范围外的人重新授权进来。保存使用当前治理修订号进行并发校验，并写入审计和版本化知识治理事件；后续文档版本继续继承最近版本的访问策略。成员限制、部门限制、任务/角色限制和数据分级在服务端组合，关键词、向量、关系扩展及引用读取均执行同一授权策略，不依赖前端隐藏。

## 后续优化优先级

### P0：试点用户体验

1. 增加应用内原文阅读器和页码/工作表深链接。

### P2：生产化

## 证据边界

- 所有截图来自真实管理后台和真实知识库，不是静态设计稿。
