# 知识库向量检索与智能体接入核查

核查日期：2026-08-03

## 核查结论

当前项目的代码已经实现文档解析、切片、Embedding、pgvector 向量查询、关键词与向量融合、可选 Reranker、权限过滤、智能体知识范围绑定、知识注入和引用校验等链路。

但当前运行环境并未真正启用这条语义 RAG 链路：Embedding 与 Reranker 均未配置，数据库中没有任何向量记录，现有知识库尚处于草稿状态，现有智能体也没有绑定知识库。因此当前只能认定“文档已入库并切片”，不能认定“已完成向量化、语义召回并作为智能体知识生效”。

## 已经具备的代码能力

### 文档入库与向量化

知识入库服务会解析文件、生成切片并计算内容哈希。当语义检索开关启用时，它会批量调用 AI Runtime 生成 1536 维 Embedding，并写入 `knowledge_chunk_embeddings`。也提供对已切片版本重新构建向量的服务路径。

当前环境关闭了语义开关，因此入库任务即使显示成功，也只代表解析、切片和基础索引成功，不代表已经生成向量。

### 检索与召回

检索服务已经实现：

- 关键词/全文及 trigram 模糊候选；
- pgvector 余弦相似度向量候选；
- 关键词与向量结果的 RRF 融合；
- 可选的 Cross Encoder/Cohere-compatible Reranker；
- 关系图谱候选扩展；
- 租户、用户、组织、项目、任务、角色和数据标签权限过滤；
- 当前发布文档版本约束和引用来源信息。

在当前配置下，向量候选和 Reranker 不会运行，最多只能使用词法检索降级模式。由于现有知识库还是 `DRAFT`，普通员工和 Agent Run 的正式检索还会排除它；只有管理端受控的草稿预览可以测试草稿候选。

### 智能体知识接入

智能体版本通过 `knowledgeScope.knowledgeBaseIds` 保存绑定的知识库。Agent Run 启动后会：

1. 从已发布的智能体版本快照读取知识库范围；
2. 按提问者权限调用统一知识检索服务；
3. 将召回切片作为不可信企业数据注入模型上下文；
4. 要求模型使用精确的来源标记；
5. 在输出落库前再次校验权限、内容哈希、治理哈希和引用；
6. 向用户返回可追溯的文档、版本、章节和切片引用。

所以“把知识供智能体使用”的代码链路存在，但当前数据中 12 个智能体均未绑定知识库，实际不会获得这些文档。

## 当前阻断点

要让现有文档真正成为智能体知识，至少需要同时关闭以下阻断项：

1. 配置获准使用的 Embedding 服务，并将 API 与 AI Runtime 的语义检索开关同时启用；
2. 对当前切片生成真实 1536 维向量，确认非空向量覆盖率为 100%；
3. 配置并验证 Reranker，或明确接受仅 RRF、不做重排的阶段性降级；
4. 完成知识库治理/发布，使知识库从 `DRAFT` 进入 `ACTIVE`；
5. 在智能体角色蓝图的版本治理流程中选择知识库，完成审核、评测和发布；
6. 用企业问题集验收 `HYBRID` 模式、非零向量候选、Rerank 结果、权限负例和引用准确性。

## 可用性判断

- 文档保存、解析、切片：可用。
- 关键词检索代码：已实现；当前草稿知识库只适合管理端预览，尚未对员工/智能体正式生效。
- 向量化：代码已实现，当前环境未启用，当前数据为 0 条向量。
- 向量检索与语义召回：代码已实现，当前运行未启用。
- Reranker：代码已实现兼容接口，当前运行未配置。
- 智能体知识绑定：代码链路已实现，当前没有任何实际绑定。
- 企业级 RAG：当前不达标，不能宣称已投入使用。

## 验收标准

后续启用后不应只看健康接口为 200，而应同时满足：

- 当前已发布切片数量大于 0；
- 指定 Embedding 模型的向量数量等于已发布切片数量；
- `semanticCoverage = 1`；
- 检索响应为 `HYBRID` 且 `vectorCandidateCount > 0`；
- 启用重排时响应为 `CROSS_ENCODER`，并返回准确的 Reranker 模型；
- 至少一个已发布智能体版本绑定活动知识库；
- 员工提问能够返回正确答案和可打开的文档版本/切片引用；
- 无权限用户无法召回同一文档；
- Embedding 或 Reranker 故障时界面明确显示降级，不能冒充语义检索成功。
