# 知识库部门与成员访问范围

- 日期：2026-08-06
- 状态：已实现并在本地开发环境验收

## 1. 产品语义

知识归属和知识访问是两个正交维度：

- 归属：公司、部门、项目、成员四类同级空间，回答资料放在哪里。
- 访问：全公司、指定部门、指定成员，回答哪些员工及其智能体可以使用。

访问模式如下：

```text
全公司成员可访问
或
受限访问 = 命中任一指定部门（可包含下级） OR 命中任一指定成员
```

指定成员不会绕过基础员工条件。用户必须仍处于启用状态，并至少具有一条位于有效部门的有效任职关系。

## 2. 管理员流程

1. 在“上传资料”中先选择知识归属。
2. 选择“全公司成员可访问”或“仅指定部门或成员可访问”。
3. 受限模式可以搜索并多选部门、选择是否包含下级部门，也可以按姓名、邮箱或部门搜索成员。
4. 同一批文件共享创建时选择的知识库访问范围。
5. 向已有知识库添加文件或新版本时，页面明确展示并继承当前知识库访问范围。
6. 知识库详情标题下显示当前范围摘要；设置页可修改范围。

知识归属不会自动推导访问范围。例如资料归入“成员知识 / 张三”，管理员仍需明确选择全公司或受限访问。

## 3. 数据模型与迁移

已有 `knowledge_base_org_units` 继续保存部门范围和 `include_children`。新增 `knowledge_base_members` 保存：

- `tenant_id`
- `knowledge_base_id`
- `user_id`
- `created_at`

表使用租户复合外键、唯一索引、成员反向查询索引、`FORCE RLS` 和最小角色授权。两类范围都为空保持历史语义，即全公司有效成员可访问，因此既有知识库无需数据回填。

前向迁移为 `20260806000300_knowledge_member_access_scope`。

## 4. 公共契约与服务端校验

知识库响应新增 `memberUserIds`。创建和更新请求支持 `memberUserIds`，部门继续使用显式的 `orgUnitScopes`：

```json
{
  "orgUnitScopes": [
    {
      "orgUnitId": "00000000-0000-7000-8000-000000000010",
      "includeChildren": true
    }
  ],
  "memberUserIds": ["00000000-0000-7000-8000-000000000101"]
}
```

服务端执行：

- 去重部门和成员 ID。
- 部门必须属于当前租户并处于启用状态。
- 成员必须属于当前租户、处于启用状态，并具有有效任职和有效部门。
- 访问范围变化进入管理审计摘要。
- 浏览器不提交成员姓名作为授权依据。

## 5. 智能体检索执行

检索服务在读取候选知识库时同时加载部门范围和成员范围，并使用当前用户执行：

1. 用户状态校验。
2. 有效任职和有效部门校验。
3. 全公司/部门继承/指定成员访问范围校验。
4. 角色智能体的组织边界过滤。
5. 文档版本治理、发布状态和资源级过滤。
6. 在 Agent Run 发送证据前重新检查切片可访问性。
7. 用户打开引用原文时再次执行同样的知识范围校验。

因此，前端隐藏知识库或智能体曾经检索成功，都不能替代服务端的最新访问判断。

## 6. Knowledge Gateway 边界

`knowledge_base_members` 属于知识边界内部表。项目、成员、智能体、评测和第三方系统不得联表查询；需要查询可访问知识或按成员选库时，必须扩展传输中立的 Knowledge Gateway DTO 或调用公共知识 API。

本次没有向 Gateway 泄漏 Prisma 类型、表记录、Qdrant collection 名或对象存储 key，架构红线测试保持通过。
