# 用户表单去技术化与知识上传整改

## 背景与目标

本轮整改面向非技术员工和业务管理员，目标是让用户只填写业务内容，不再复制内部 ID、编写 JSON、手算哈希或维护数组字符串；知识资料以文件上传为主，文本粘贴仅作为补充入口。后端既有契约和治理数据保留，系统生成字段仍由可信服务端校验。

## 范围与盘点

任务启动时对管理端和桌面端表单的静态盘点基线为：约 371 个 `input/textarea`，其中 118 个属于明显技术型自由输入；保守整改条目中，41 项应自动生成或计算、46 项应改为选择器、5 项应继承上下文或权限策略。

最终重新扫描 71 个非测试 TSX 文件：

- `input` 205 个、`textarea` 68 个，共 273 个，较基线净减少 98 个原生输入控件。
- 全部文件选择控件 4 个，其中知识中心 2 个；另外 2 个用于高级评测结果包导入。
- 面向用户的源码中，禁止模式命中为 0：原始 JSON 编辑、JSON.parse 表单处理、UUID/SHA/Revision/Schema/Payload 命名输入、逗号或换行 ID 数组、手填 Evidence ID/版本、代码覆盖、占位 ID。
- 273 个保留控件用于名称、说明、日期、金额、业务选项、搜索选择、消息内容等正常业务输入；这项数量不等于技术字段数量。

## 已实施改动

### 普通员工路径

- 任务证据改为“上传文件、选择现有文档、粘贴资料链接 + 业务说明”，证据编码、来源记录、版本、时间、权限和内容校验值由服务端生成。
- 交付物提交不再要求 SHA-256；业务描述和真实证据提交后，由服务端生成稳定资料地址和校验值。
- 协同命令不再显示或解析 JSON。交付、验收、升级分别从当前任务的真实交付物、验收记录、可信证据和可用负责人中选择；拒绝和取消只填写业务原因与影响。
- 删除协同命令中的零 UUID、占位证据和“请替换 ID”伪数据。目录未返回真实记录时提交按钮保持禁用。
- 工具调用根据工具输入定义生成业务字段；原始 JSON 输入和普通员工可见的 Schema 预览已移除。
- 记忆和经验的权限范围、用途与有效期优先继承任务和角色策略，不要求员工输入标签数组。

### 管理后台业务配置

- 经营主链的通用契约编辑器改为字段化业务表单；关联实体使用名称选择器，系统字段隐藏并保留服务端校验。
- 管理端不再通过伪造文件地址、哈希和证据 ID 提交交付物。草稿交付物统一引导到员工任务工作台的文件/文档/链接流程。
- 知识治理中的组织、角色、版本、证据和模拟用户改为受控选择器；本体和图谱修正使用模板与字段向导。
- 角色蓝图、角色任命、组织变更、营销目标、经验治理和 FinOps 关联对象均改为真实目录选择或上下文带出。
- FinOps 成本复核的 Evidence ID/版本改为“已验证可信证据”选择器，证据版本自动带出；预算代码覆盖入口删除并由系统按范围、币种和期间生成。
- SCIM 连接器内部标识由显示名称和冲突后缀自动生成，不再要求管理员理解编码规则。
- AI 评测只允许选择数据集、对象、证据和 Runner，并通过文件导入真实 Runner 结果包；不再手填哈希、签名和结果 JSON。

### 知识资料入口

- 知识中心提供“批量导入企业知识”：一次最多 20 个文件，每个不超过 20 MB。
- 单个知识库提供“上传知识文件”和“上传文件新版本”。
- 当前界面明确支持 PDF、DOCX、XLSX、TXT、MD；标题默认取文件名，系统继续执行解析、切片和索引。
- 网页导入保留为连接器式来源。
- “粘贴文本”保留在折叠的“更多录入方式”中，不再作为唯一或主入口。
- 上传结果展示处理中、成功、失败和失败原因；失败不会伪装为导入成功。

## 保留的专业配置及理由

以下字段不是可由系统安全伪造的业务字段，只在 Owner/Admin 的高级设置或连接向导中保留：

- 飞书 App ID、App Secret。
- OIDC Issuer、Discovery URL、Client ID、Client Secret。
- 模型供应商、模型名称、凭据保险库引用。
- 工具 Endpoint Ref、允许访问的服务地址。
- 外部 Runner 导出的 JSON 结果包文件。

这些值必须由外部平台或运维系统真实提供。界面不会自动生成假凭据。运行治理、审计、知识图谱中的 JSON/哈希只作为高级只读诊断信息展示，不是可编辑表单。

## 风险与未验证项

- 本轮验证了上传界面、文件格式约束、API 契约和处理状态，但未用客户真实 PDF、DOCX、XLSX 样本评估解析准确率、复杂表格还原、扫描件 OCR 和对象存储稳定性。
- 需要真实外部凭据的飞书、OIDC、模型、Embedding、Reranker、Runner 等能力未在本轮伪造验收。
- 数据库/RLS 集成测试本轮未启用对应集成环境，155 项被测试配置明确跳过；不能用单元测试替代生产数据库验收。
- Admin 和 Desktop 的生产包仍有大于 500 kB 的单包警告，功能不受影响，但后续应按路由拆包。

## 可交付判断

表单去技术化和知识文件优先入口已形成可提交、可验证的代码闭环：普通员工无需填写 JSON、数组、UUID、SHA、内部版本或来源记录，管理端关联对象主要通过选择器和上下文处理，知识资料可以通过企业常见文件格式上传。代码层面达到本轮可交付标准。

企业生产可用性仍需在独立验收环境补做真实文件解析/OCR/向量检索、外部连接器和数据库权限集成测试；这些未验证项不应被表述为已经通过。
