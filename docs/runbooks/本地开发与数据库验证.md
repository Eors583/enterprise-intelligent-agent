# 本地开发与数据库验证 Runbook

## 1. 两种运行模式

API 支持两种 Repository Driver：

- `memory`：默认模式，只用于桌面界面、契约和快速测试；进程重启后会话消失。
- `prisma`：连接 PostgreSQL，启用真实认证、动态组织、知识库、会话账本、Outbox、Audit、受限角色和 RLS。

`NODE_ENV=production` 时禁止 `memory`。共享测试、预生产和生产都必须使用持久化适配器与可信身份来源。

## 2. 首次准备

在仓库根目录执行：

```powershell
Copy-Item .env.example .env
pnpm install
pnpm setup:electron

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".\services\ai-runtime[dev]"
```

确认 Node.js 为 24.x、pnpm 为 11.x、Python 为 3.12+。如果系统默认 Node 版本较旧，应先切换运行时，不要忽略 `engines` 警告。

## 3. 启动并初始化基础设施

```powershell
pnpm dev:infra
pnpm db:validate
pnpm db:generate
pnpm db:migrate
pnpm db:seed
pnpm db:seed
pnpm test:db
```

两次 `db:seed` 是有意的：seed 使用 upsert，第二次必须成功且不能新增重复目录数据。它在同一事务内执行 `SET LOCAL ROLE enterprise_agent_provisioner` 和 transaction-local `app.tenant_id`。如果 003 migration 尚未应用、当前数据库登录没有 provisioner membership，或者角色权限不足，seed 应直接失败，不能回退到高权限写入。

当前 migration 顺序和职责：

| Migration                                   | 职责                                                                                         |
| ------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `20260715000100_initial`                    | 基础 schema、`ENABLE/FORCE RLS`、应用角色初始引导                                            |
| `20260715000200_tenant_scoped_foreign_keys` | `(tenant_id, id)` 候选键与 21 条业务复合外键；发现既有非法引用时原子失败                     |
| `20260715000300_security_policies`          | `RESTRICTIVE tenant_isolation`、app/provisioner 最小权限、默认权限回收、消息活跃参与者触发器 |
| `20260715000400_im_outbox_delivery`         | Outbox 租约/回执、既有事件收件人回填、专用 Worker 角色与跨租户队列 RLS                       |
| `20260715000500_im_delivery_unknown`        | `first_attempted_at`、`UNKNOWN` 状态及腾讯去重窗口外禁止自动重发                             |
| `20260715000600_auth_admin_knowledge`       | 首方认证/会话、租户角色、动态组织树、知识库、auth/admin 能力角色与 RLS                       |

`test:db` 不只是检查连接，它会验证：

- 应用事务实际降权为 `enterprise_agent_app`；
- 缺少 tenant context 时默认看不到业务数据；
- 错误 tenant context 不能读取其他租户；
- 所有受保护租户表都启用并强制 RLS，租户策略保持限制性和默认拒绝；
- 21 条业务关系已使用复合租户外键，跨租户父资源与不存在父资源都被拒绝；
- 应用角色不能读取 `_prisma_migrations` 或写人员目录，provisioner 不能读取会话账本，auth/admin 角色只能访问职责内表；
- 数据库触发器拒绝不属于活跃参与者的消息发送者；
- PostgreSQL 模式下 direct 会话并发复用、消息幂等/冲突、离开成员恢复和 `lastMessageAt` 单调性有效；
- 跨租户会话返回 404，暂停租户在进入业务域前返回 403。
- 两个 Worker 使用 `SKIP LOCKED` 时不会领取同一事件，过期租约可恢复且旧持有者不能迟到提交；
- 真人/Agent-only 本地回执、指数退避、FAILED 与 UNKNOWN 状态转换，以及 Outbox 角色无法读取业务表。

当前 `test:db` 已固化上述关键安全边界；逐表逐动作完整授权矩阵、未来新表默认权限以及目标 Managed PostgreSQL 的角色能力仍是 migration 审查与部署验收项，不能只依赖 migration SQL 的声明。

Migration/seed 脚本使用根 `.env`，不存在时只会回退到 `.env.example` 的本地开发值。示例环境由同一 Docker 管理登录完成 migration，并通过 `SET LOCAL ROLE` 走受限路径，仅用于本地验证。生产必须按任务注入不同 Secret：普通 API、认证、管理和 Worker 分别使用 `DATABASE_URL`、`AUTH_DATABASE_URL`、`ADMIN_DATABASE_URL`、`OUTBOX_DATABASE_URL` 的不同数据库用户名；provisioning 和 migration 身份也不得暴露给应用进程。

## 4. 使用 PostgreSQL 启动应用

把根 `.env` 设置为：

```dotenv
REPOSITORY_DRIVER=prisma
IM_OUTBOX_ENABLED=true
IM_PROVIDER=local
REGISTRATION_MODE=open
ALLOW_DEV_IDENTITY_HEADERS=false
AUTH_TOKEN_PEPPER=replace-with-at-least-32-random-characters
```

然后分别启动或一次启动：

```powershell
pnpm dev:api
pnpm dev:ai
pnpm dev:admin
pnpm dev:desktop

# 或
pnpm dev
```

关键检查：

- `GET http://127.0.0.1:3000/health/live`
- `GET http://127.0.0.1:3000/health/ready`，应返回 `adapter: prisma`
- `http://127.0.0.1:4173`，使用登录后的管理后台验证组织和知识库
- Electron 登录后验证 bootstrap、组织目录和 conversations
- `GET http://127.0.0.1:8100/health/ready`

本地 seed 使用企业短地址 `future-collaboration` 和密码 `DevPassword!2026`：`lin.xiao@example.local` 为 OWNER，`zhou.rui@example.local` 为 ADMIN，`chen.yao@example.local` 为 MEMBER。仅限本地使用。

桌面端从通讯录点击“联系本人”或“联系智能体”后，服务端会创建或复用会话。消息发送只有在 API 返回成功后才进入本地缓存，失败重试复用原 `clientMessageId`。

这里的“联系智能体”会建立或复用 Agent direct 会话，并在 Prisma 模式、Agent Run Worker 与 AI Runtime Provider 均正确启用时创建后端 Run。运行成功后，智能体消息会先写入 PostgreSQL 权威消息账本，再由桌面端同步展示；仅有 Agent 收件人的普通 IM 事件仍会记录 `skipped/no_human_recipients` 回执。开发默认 `noop`、模型不可用或 Run 失败时不会伪造回复，看到 Agent 回复仍必须以服务端真实返回的 `sender.type=agent` 为准。

### 4.1 验证本地 IM Outbox

发送一条真人 direct 消息后，可用只读查询核对：

```sql
SELECT status, attempts, provider_name, provider_receipt, last_error
FROM outbox_events
WHERE event_type = 'message.created.v1'
ORDER BY created_at DESC
LIMIT 5;
```

开发 Local Provider 应把真人事件转为 `PUBLISHED/local/accepted`。Agent-only 事件也会转为 `PUBLISHED`，但回执必须是 `skipped/no_human_recipients` 且投递人数为 0。`FAILED` 是确定性终态；`UNKNOWN` 表示上游可能已收到，禁止直接把它改回 `PENDING` 重发。

### 4.2 切换腾讯云 IM

仅通过当前 PowerShell 会话、Secret Manager 或 ConfigMap 注入：

```powershell
$env:IM_PROVIDER='tencent'
$env:TENCENT_IM_SDK_APP_ID='<SDKAppID>'
$env:TENCENT_IM_ADMIN_USER_ID='<管理员UserID>'
$env:TENCENT_IM_SECRET_KEY='<服务端Secret>'
$env:TENCENT_IM_API_BASE_URL='https://console.tim.qq.com'
$env:TENCENT_IM_HTTP_TIMEOUT_MS='5000'
$env:IM_PROVIDER_TIMEOUT_MS='10000'
pnpm dev:api
```

启动前必须已完成腾讯账号导入，并确保内部账号映射策略保持不变。不要把 Secret/UserSig 写入 `.env`、Electron、日志或测试 fixture。没有真实腾讯配置时，只能宣称 Local 链路和 Tencent Mock 契约通过，不能宣称公网端到端通过。

## 5. AI Runtime 模式

AI Runtime 不自动读取 `.env`，避免生产进程意外加载工作目录中的明文 Secret。默认 `noop + memory` 仅用于开发，不会出网；调用 execute 会得到明确失败，不会生成模拟回答。

连接经过批准的 OpenAI-compatible Provider 前，在进程管理器或当前 PowerShell 会话注入：

```powershell
$env:AI_RUNTIME_ENVIRONMENT='development'
$env:AI_RUNTIME_DRIVER='openai_compatible'
$env:AI_RUNTIME_STORE_DRIVER='memory'
$env:AI_RUNTIME_OPENAI_BASE_URL='https://provider.example/v1'
$env:AI_RUNTIME_OPENAI_API_KEY='<从 Secret Manager 注入>'
$env:AI_RUNTIME_OPENAI_MODEL='<已批准的部署名>'
pnpm dev:ai
```

不要把真实 API Key 写入 `.env`、命令历史、日志、截图或测试 fixture。进入共享环境前还必须实现持久化 RunStore 和服务间 JWT/mTLS；生产配置会拒绝内存 RunStore。

当前适配器只调用非流式 `POST {BASE_URL}/chat/completions`，不解析附件；包含附件的 Run 会明确失败。`AI_RUNTIME_STORE_DRIVER=postgres` 只是预留选择，仓储适配器尚未实现，直接选择会 fail-closed。

## 7. 当前不可作为生产验收的能力

- 身份：首方密码登录、token 轮换/吊销和桌面多账号已经实现；尚未完成 OIDC/SAML、SCIM、MFA、密码重置、成员邀请、登录限流和设备会话管理。
- 管理与知识：组织/成员/知识治理已经实现；尚无文件摄取、搜索、向量索引、RAG、审计查询 UI 和复杂资源级授权。
- 消息：可靠 Outbox 与腾讯 outbound adapter 已实现，但尚无真实腾讯凭据验收、账号 provisioning 工具、回调 Inbox/验签/幂等、腾讯客户端 SDK 实时同步、群聊、分页游标、已读/撤回和富媒体。
- AI：API 尚未通过服务身份调用 Runtime，RunStore 仍为内存，缺少队列/租约、工具审批、计价、审计和 OpenTelemetry。
- 运维：尚未完成生产 Secret、独立数据库登录凭据、备份恢复演练、签名发布、自动更新和目标云环境权限验证。

## 8. 停止服务

停止开发进程后运行：

```powershell
pnpm dev:infra:down
```

该命令保留 PostgreSQL/Redis volume。不要在含有需要保留数据的环境中使用 `down -v` 或数据库 reset；需要重建本地数据时先确认目标 Compose project 和 volume，再执行显式清理。
