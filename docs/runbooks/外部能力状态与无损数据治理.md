# 外部能力状态与无损数据治理

## 1. 状态口径

配置生命周期与运行可用性必须分开显示。任何页面、接口说明或验收报告都不得把“配置已启用”
写成 `ONLINE`，也不得把本地配置存在写成外部能力已验证。

| 能力                             | 未配置或无证据时的唯一允许口径     | 只有何时可以提升                                                             |
| -------------------------------- | ---------------------------------- | ---------------------------------------------------------------------------- |
| 飞书目录                         | 未配置 / 同步不可用                | 新 Secret 在线换取 Token、部门与成员权限均通过；完成同步后才显示本次同步成功 |
| Manus                            | 未配置 / 不可用 / 供应商仅返回终态 | 真实 Run 回执通过；只有供应商提供多个真实 delta 才能声明增量流式             |
| Embedding                        | 未配置 / 语义未就绪 / 不可连接     | 非空已发布切片由指定模型生成真实向量且覆盖率为 100%                          |
| Reranker                         | 未配置 / 语义未就绪 / 不可连接     | 真实候选经过指定 Reranker，企业问题集与延迟门禁通过                          |
| 企业 IdP / 邮件 / 对象存储 / OCR | 未配置 / 不可用                    | 真实外部环境完成签名、投递、存取或解析验收                                   |
| OTLP / SIEM                      | 未配置 / 导出不可用 / 导出证据过期 | Collector/SIEM 收到最新成功导出并且未超过 stale 窗口                         |

智能体记录中的 `ONLINE` 是历史数据库配置枚举，只允许在用户界面翻译为“配置已启用”。员工端
是否开放联系必须继续复核 Runtime、可信路由、精确允许列表、熔断器和近期真实成功回执。配置已
启用但上述证据缺失时，入口应禁用并显示具体阻断原因。

知识检索的 `HYBRID` 只允许在非空已发布切片、当前指定 Embedding 模型覆盖率 100% 且 Reranker
就绪时出现。空集合、任意历史向量或只启用开关都不能通过门禁。

## 2. 飞书 Secret 轮换阻断

曾出现在聊天、工单、截图、日志或源码中的 App Secret 已视为泄露，不得再次粘贴到管理端、环境
变量或验收脚本。真实联网验收前必须：

1. 在飞书开放平台轮换同一 App ID 的 Secret；
2. 清理旧 Secret 的环境变量和 Secret Manager 版本；
3. 只把新 Secret 注入服务端凭据入口，不进入命令行参数、日志、数据库报告或客户端；
4. 在管理端确认“新生成且未暴露”后执行在线权限探测；
5. 记录轮换时间、执行人和变更单，不记录 Secret 原文。

管理端的确认框是人为防误用门禁，不是 Secret 泄露检测器。直接 API 调用和部署环境仍必须由
Secret Manager、最小权限和轮换流程约束。

## 3. 隔离恢复库只读治理评估

[`Invoke-EnterpriseDataGovernanceDryRun.ps1`](../../infra/scripts/Invoke-EnterpriseDataGovernanceDryRun.ps1)
只运行 `READ ONLY` 事务并以 `ROLLBACK` 结束。它不会更新、删除、复制或重放任何事件，也不会
释放 `UNKNOWN` Run 的额度占位。脚本评估：

- Outbox 路由注册、fact-only 映射、缺失 delivery 和隔离事件；
- 已到可信终态但仍保留预留额度的上限结算候选，以及必须继续保守占位的 `UNKNOWN` Run；
- `ONTOLOGY.MAPPING.MISSING` 实例冲突按 predicate、subject type、object type 聚合后的
  schema-gap 数量；
- 非当前 READY 文档版本及其图谱证据，作为候选/历史投影回填的待人工分类集；
- 当前迁移集是否已提供图谱投影生命周期与 schema-gap 聚合能力。

运行前必须先使用仓库备份和恢复脚本，验证备份 SHA-256，并把备份恢复到名称含
`governance`、`repair`、`restore` 或 `rehearsal` 的独立数据库。脚本拒绝两个受保护验收库，
也拒绝直接连接备份源数据库。

## 4. 从 dry-run 到受控修复

当前脚本故意不提供 `-Apply`。本轮已经在
`enterprise_agent_restore_defect_fix_20260729_restore_rehearsal` 完成只读演练，结果为
`read-only-dry-run-complete`、`transactionReadOnly=true`、`mutationsPerformed=0`、
`historyDeleted=false`。当前 Seed 租户没有候选、无效、隔离或 schema-gap 待治理记录；
这个空结果只证明演练没有修改数据，不能替代真实存量分类，也不能授权手工 SQL 更新源环境。

后续受控修复只能通过迁移集提供的、可重放且幂等的数据库命令或受信后台服务执行，并满足：

- 先在隔离恢复库完整演练，再对指定租户执行；
- 每个修复类别记录不可变 Audit Event，包含变更单、操作者、前后计数和算法版本；
- 不删除历史 Outbox、Run、关系、冲突、文档版本或审计记录；
- fact-only 只修改路由分类，不伪造投递成功；DELIVERY 继续沿用原 Event ID；
- FAILED/UNKNOWN 不批量改成功、不复制事件、不盲目重放；
- `UNKNOWN` Run 在可信对账前继续占用并发和预留；
- 候选/历史版本先分类再回填投影生命周期，不能把非当前 READY 版本自动视为 ACTIVE；
- schema-gap 聚合保留原实例冲突和关系证据，仅新增聚合治理视图或记录。

只有 dry-run、隔离 Apply 演练、审计链复算、RLS/ACL 与备份恢复复验全部通过，才允许创建面向
源环境的受控修复命令。
