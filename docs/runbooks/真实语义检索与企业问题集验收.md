# 真实语义检索与企业问题集验收

`tools/semantic_acceptance` 是一个独立、默认离线的验收工具。它不访问数据库、不管理服务，也不保存供应商密钥。只有显式传入 `--allow-network` 后，它才会请求指定的已部署 API 与 AI Runtime；AI Runtime 是否继续访问外部供应商，由部署环境自己的配置决定。

工具把两类证据分开，且两类都通过才返回 `PASS`：

1. **Provider smoke**：读取 Runtime capability，并实际调用 Embedding 与 Reranker。它核对精确模型名、Embedding 维度为 1536、两个不同输入均得到有限非零且不相同的向量，以及 Reranker 能把语义相关但排在输入末尾的文档以严格分差排到第一。
2. **企业问题集**：逐条调用管理端检索测试接口，计算宏平均 Recall@5、MRR、nDCG@10、无答案准确率、客户端墙钟 P95，并统计命中禁止 chunk/document/knowledge-base 和暴露禁止知识库 scope 的 ACL 泄漏事件。

Capability 或 smoke 成功只能证明部署链路可调用，不能替代真实企业问题集。反过来，问题集指标达到阈值但 provider smoke、模型名、真实向量候选或 cross-encoder 证据失败，也不能通过。

Provider smoke 是前置门禁；它失败时工具不会继续发送整批检索请求，避免在已知错误的 provider 配置上产生额外调用成本。报告会把问题集评估标记为未执行，而不是用空指标伪造结果。

## 1. 准备脱敏 JSONL

问题集建议放在已被 Git 忽略的 `.data/semantic-acceptance/`，不要提交员工原始问题、文档原文、令牌或供应商密钥。每行是一个 JSON 对象：

```json
{
  "id": "travel-policy-001",
  "query": "出差回来以后要交哪些材料？",
  "knowledgeBaseId": "10000000-0000-4000-8000-000000000001",
  "userId": "20000000-0000-4000-8000-000000000001",
  "expectedNoAnswer": false,
  "semanticRequired": true,
  "relevance": {
    "30000000-0000-4000-8000-000000000001": 3,
    "30000000-0000-4000-8000-000000000002": 1
  },
  "forbiddenChunkIds": ["30000000-0000-4000-8000-000000000099"],
  "forbiddenDocumentIds": [],
  "forbiddenKnowledgeBaseIds": [],
  "limit": 10
}
```

字段约束：

- `id`：不含业务原文的稳定用例编号。
- `query`：经过脱敏的真实表达或由真实表达等价改写的问题。
- `knowledgeBaseId`、`userId`：目标验收租户中的 UUID。每条用例显式指定模拟用户，避免默认使用管理员导致 ACL 验收失真。
- `expectedNoAnswer`：期望系统拒答时为 `true`。拒答用例的 `relevance` 必须为空。
- `semanticRequired`：普通答案与知识缺口用例应为 `true`；纯 ACL 拒绝、目标用户按设计无权读取任何候选时可为 `false`。所有可回答用例强制为 `true`。
- `relevance`：以 chunk UUID 为键的人工相关性标注，等级范围 `(0, 3]`。Recall/MRR 将其视为二元相关，nDCG 使用分级相关性。
- 三个 `forbidden*` 列表：目标用户绝不能看到的 chunk、document 或 knowledge base。应覆盖同部门、跨部门、父子部门、已停用成员和管理员等不同主体。
- `limit`：范围 10～20，保证 nDCG@10 有足够的检索窗口。

默认覆盖门槛是至少 200 条，其中可回答问题至少 150 条、无答案问题至少 25 条、有 ACL 禁止标注的用例至少 25 条。建议首批控制在 200～500 条，并覆盖真实部门、文件类型、计算题、关系题和业务 API 题；降低门槛只适合调试，不构成企业验收。

先做完全离线的结构与覆盖检查：

```powershell
python -m tools.semantic_acceptance `
  --validate-dataset-only `
  --dataset .\.data\semantic-acceptance\enterprise-questions.jsonl
```

输出中的 `networkAccessed` 必须为 `false`。离线校验不计算检索质量，也不会生成 `PASS` 验收报告。

## 2. 部署前置条件

- AI Runtime 已通过进程 Secret/ConfigMap 配置真实 Embedding 与 Reranker provider；供应商密钥不能写入仓库、JSONL、命令行参数或报告。
- API 已启用语义检索与 rerank，并指向上述 Runtime。
- 验收知识库必须存在已发布、非空的切片，并已使用指定模型生成 1536 维向量。空知识库不能通过问题集覆盖门槛和可回答用例。
- `--expected-embedding-model` 与 `--expected-rerank-model` 使用部署审批过的精确版本名，不使用会静默漂移的自定义别名。
- 管理 API 使用短期、最小权限的管理员 bearer token。工具只从环境变量读取，不提供明文 token 参数，也不会把 token 写入日志或报告。
- 如果 Runtime 位于带服务认证的私有代理后，将短期 token 注入可选的 `SEMANTIC_ACCEPTANCE_RUNTIME_TOKEN`；loopback 开发 Runtime 无此边界时可不设置。
- 除 `localhost`、`127.0.0.1` 和 `::1` 外，目标地址强制使用 HTTPS；工具拒绝 URL 内嵌凭据、query/fragment 和 HTTP redirect，避免 bearer token 被转发或明文传输。

PowerShell 中可交互注入 API token，避免写入命令历史：

```powershell
$secureToken = Read-Host 'Short-lived admin token' -AsSecureString
$env:SEMANTIC_ACCEPTANCE_API_TOKEN = [System.Net.NetworkCredential]::new('', $secureToken).Password
```

## 3. 执行真实验收

```powershell
python -m tools.semantic_acceptance `
  --allow-network `
  --dataset .\.data\semantic-acceptance\enterprise-questions.jsonl `
  --api-base-url http://127.0.0.1:3000/api/v1 `
  --runtime-base-url http://127.0.0.1:8100 `
  --tenant-id 00000000-0000-4000-8000-000000000001 `
  --expected-embedding-model embedding-model-immutable-version `
  --expected-rerank-model reranker-model-immutable-version `
  --report .\.data\semantic-acceptance\acceptance-report.json
```

默认质量阈值：

| 指标           |  默认门槛 |
| -------------- | --------: |
| Recall@5       |    ≥ 0.80 |
| MRR            |    ≥ 0.70 |
| nDCG@10        |    ≥ 0.70 |
| 无答案准确率   |    ≥ 0.90 |
| 客户端墙钟 P95 | ≤ 3000 ms |
| ACL 泄漏事件   |         0 |

可用 `--min-recall-at-5`、`--min-mrr`、`--min-ndcg-at-10`、`--min-no-answer-accuracy`、`--max-p95-ms` 和 `--max-acl-leaks` 显式传入审批后的门槛。生产验收不应把 `--max-acl-leaks` 放宽到大于 0。

退出码：

- `0`：所有 smoke、语义证据、覆盖和质量阈值均通过，或仅执行的离线 JSONL 校验通过。
- `1`：已完成真实验收，但 provider、请求、语义证据、质量或 ACL 任一项失败。
- `2`：参数、凭据环境变量、JSONL 结构或覆盖门槛不合法，真实验收未成立。

报告不包含 query、文档 excerpt、向量或 token，只保留问题集 SHA-256、用例 ID、返回 chunk UUID、指标和失败证据。报告本身仍属于企业内部验收材料，应进入受控存储。

## 4. 指标与边界

- Recall@5、MRR 与 nDCG@10 只在可回答用例上计算，采用逐问题宏平均；无答案准确率只在 `expectedNoAnswer=true` 的拒答用例上计算。
- P95 使用每个管理 API 请求的客户端墙钟时间和 nearest-rank 算法，顺序执行，不用服务端自报耗时替代；服务端 `elapsedMs` 仅作为诊断证据。
- 任一用例请求失败或响应契约无效会使整次验收失败，不会通过跳过失败问题来抬高指标。
- `semanticRequired=true` 时必须看到 `HYBRID`、精确 Embedding 模型、非零向量候选、非零语义覆盖、`CROSS_ENCODER`、精确 Reranker 模型、无降级原因以及结果级语义/rerank 分数；LEXICAL 结果不能冒充语义验收。
- ACL 泄漏数只对 JSONL 中明确列出的禁止对象负责。问题集必须由数据负责人维护反例矩阵，并在组织和权限模型变化时更新。
- Harness 通过受信任的 Runtime 观察 provider。若需要证明请求到达某个具体供应商账户，还必须把供应商审计/账单 request ID 与本报告关联；本工具不会伪造这一外部证据。
